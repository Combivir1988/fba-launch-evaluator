# Quickstart: проверки spec 025

Девять проверок. **Три из них — ворота**: они обязаны падать на неправильной реализации, и это проверяется подстановкой, а не доверием.

---

## Ворота 1 (SC-001) — ниша без повторяющихся различий говорит это вслух

**Пишется ПЕРВЫМ из тестов ядра, до реализации.**

1. Фикстура: ниша, где семьи вариаций есть, но ни одно поле не набирает двух значений с долей ≥10 % выручки поля.
2. Ожидание: `status === "no_repeating"`, `items` пуст, `note` содержит утверждение, что линейку здесь не строят.
3. Отдельно: ниша с полем из сотен уникальных значений и максимальной частотой смены (живые случаи — «Уникальные фичи» 95,8 % / 334 значения и «Аромат» 95,8 % / 328). Ожидание: это поле **не выбрано** осью, оно в `axisRejected` с причиной, линейка построена по следующей оси.

**Проверка подстановкой**: убрать из правила условие «не меньше двух весомых значений» — тест обязан упасть, и упасть именно на этих пунктах.

---

## Ворота 2 (SC-002) — чужое слово не порождает варианта

**Пишется до реализации.**

1. Фикстура: ниша, где среди ключей есть слово с огромным объёмом, отсутствующее среди значений полей (живой случай — `duct` 201 851 SV в нише joist tape, где это duct tape, чужой товар).
2. Ожидание: варианта с этим словом нет; ни одно значение `items[].value` не взято из ключей.

**Проверка подстановкой**: разрешить порождать вариант по слову из ключей — тест обязан упасть.

---

## Ворота 3 (SC-003) — работа чисто добавочная

**Делается РАНЬШЕ появления поля в расчёте.**

1. Исключить `productLine` из контрольного отпечатка как добавочное поле.
2. Прогнать все фикстуры. Отпечаток обязан остаться **прежним на всех**.
3. Расхождение — повод остановиться и разобраться, а не обновить число.

---

## Проверка 4 — вырезание из публичной ссылки и автономного HTML (SC-005)

1. Собрать снимок публичной ссылки в обоих режимах (`full` и `no_economics`).
2. В снимке нет `results.productLine` — проверяется **содержимым**, а не кодом показа.
3. То же для автономного HTML: он кладёт в файл весь документ анализа, поэтому путь отдельный и проверяется отдельно.
4. Ловушка утечек не находит ни одного следа: ни имён осей, ни значений вариантов.

---

## Проверка 5 — цена варианта берётся из существующего расчёта

1. У варианта, под который аналоги есть: цена, число аналогов и уровень совпадения совпадают с тем, что даёт расчёт цены конфигурации для того же сочетания.
2. У варианта без аналогов: `price === null`, причина названа, цена главного **не подставлена**.

---

## Проверка 6 — три состояния спроса различимы

1. Текстовое значение латиницей, слово есть в ключах → объём назван.
2. Числовое значение → `demand.checked === false`, названо, что объём не искали и почему.
3. Текстовое значение, слова в ключах нет → искали, не нашли; это не ноль.
4. Выгрузки ключей нет → не искали, названо.
5. Слово — имя бренда → в объём не входит.

---

## Проверка 7 — шесть исходов различимы

По одной фикстуре на каждый: `no_xray`, `no_variations`, `no_stage2`, `no_differences`, `no_repeating`, `ok`. У каждого своя фраза; склейки нет.
