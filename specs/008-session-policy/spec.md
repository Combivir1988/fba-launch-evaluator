# Feature Specification: Длительность сеанса и автоматический выход при бездействии

**Feature Branch**: `008-session-policy` · **Created**: 2026-09-21 · **Status**: Implemented 2026-09-22 · Approved 2026-09-21 (запрос владельца: «как можно регулировать длительность сессии, например автоматически выходить при отсутствии активности»)

## Проблема

Сейчас сеанс живёт 30 дней и продлевается любой активностью — регулировать это нельзя. На общем или оставленном без присмотра компьютере анализ (себестоимость, маржа, бюджет) остаётся открытым сколь угодно долго: выхода при бездействии нет. Администратор не может ни сократить срок сеанса, ни потребовать периодического повторного входа.

## User Scenarios & Testing

### User Story 1 — Администратор задаёт правила сеансов (Priority: P1)

**Independent Test**: администратор в «Настройках» выбирает «Выход при бездействии: 30 минут» → у всех пользователей, включая уже вошедших, сеанс без активности дольше 30 минут перестаёт действовать.

**Acceptance Scenarios**:

1. **Given** администратор в разделе «Настройки», **When** он открывает блок «Сеансы», **Then** видит два правила с понятными вариантами: выход при бездействии (выключено / 15 мин / 30 мин / 1 ч / 2 ч / 4 ч / 8 ч / 24 ч) и максимальная длительность сеанса (без ограничения / 1 день / 7 дней / 30 дней).
2. **Given** правило изменено, **When** оно сохранено, **Then** действует для всех пользователей сразу, в том числе для уже открытых сеансов; повторный вход не требуется, если сеанс правилу удовлетворяет.
3. **Given** обычный пользователь, **When** он открывает «Настройки», **Then** блока «Сеансы» не видит и изменить правила не может.
4. **Given** правила не задавались, **When** приложение работает, **Then** поведение прежнее: сеанс 30 дней с продлением активностью, выхода при бездействии нет.

### User Story 2 — Выход при бездействии (Priority: P1)

**Acceptance Scenarios**:

1. **Given** включён выход при бездействии, **When** пользователь не двигает мышь, не печатает и не касается экрана дольше заданного времени, **Then** приложение завершает сеанс и показывает страницу входа с сообщением «Сеанс завершён из-за бездействия».
2. **Given** до выхода осталась минута, **When** пользователь всё ещё бездействует, **Then** появляется предупреждение с обратным отсчётом и кнопкой «Остаться»; любое действие пользователя продлевает сеанс.
3. **Given** у пользователя открыто несколько вкладок приложения, **When** он работает в одной из них, **Then** остальные вкладки не выходят из сеанса: активность общая.
4. **Given** пользователь читает дашборд и двигает мышью, но ничего не меняет, **When** проходит время, **Then** сеанс не считается бездействующим ни в приложении, ни на сервере.
5. **Given** есть несохранённые изменения, **When** наступает выход по бездействию, **Then** изменения сначала сохраняются (как при обычном автосохранении), и только потом сеанс завершается.
6. **Given** вкладка закрыта или компьютер уснул, **When** время бездействия истекло, **Then** сеанс недействителен и на сервере: возврат во вкладку или новый запрос ведут на страницу входа.
7. **Given** идёт фоновая задача (AI-анализ, патентный скан), **When** пользователь вышел по бездействию, **Then** задача доработает на сервере и её результат сохранится в анализе.

### User Story 3 — Максимальная длительность сеанса (Priority: P2)

**Acceptance Scenarios**:

1. **Given** задана максимальная длительность, **When** с момента входа прошло больше этого срока, **Then** сеанс завершается даже при непрерывной активности, и пользователь входит заново.
2. **Given** пользователь вошёл через Google, **When** сеанс завершён по любому правилу, **Then** повторный вход — той же кнопкой, без дополнительных шагов.

### Edge Cases

- Публичные ссылки «Поделиться» открываются без входа — правила сеансов на них не влияют.
- Часы компьютера переведены или вкладка «спала» — решает сервер по своему времени; приложение при возврате во вкладку сверяется с сервером.
- Администратор выставил слишком жёсткое правило и сам вышел — он просто входит снова; правило можно изменить.
- Пользователь нажал «Остаться» в предупреждении в одной вкладке — предупреждение исчезает во всех.

## Requirements

- **FR-001**: Администратор MUST иметь возможность задать время бездействия до автоматического выхода и максимальную длительность сеанса из фиксированных вариантов; остальным пользователям правила недоступны.
- **FR-002**: Правила MUST применяться ко всем сеансам, включая уже открытые, без перезапуска приложения.
- **FR-003**: Сервер MUST сам проверять оба правила при каждом обращении: сеанс, нарушающий правило, недействителен независимо от поведения браузера.
- **FR-004**: Активностью MUST считаться действия пользователя в любой вкладке приложения (мышь, клавиатура, касания, прокрутка), а не только сохранение данных.
- **FR-005**: За минуту до выхода приложение MUST предупреждать и давать остаться; при выходе — сначала сохранять несохранённое.
- **FR-006**: После выхода по правилу страница входа MUST объяснять причину.
- **FR-007**: По умолчанию поведение MUST оставаться прежним (30 дней с продлением, без выхода при бездействии).
- **FR-008**: Справка дополняется; изменение правил фиксируется (кто и когда).

## Success Criteria

- **SC-001**: При правиле «N минут» сеанс без активности недействителен на сервере не позже чем через N минут плюс одна минута.
- **SC-002**: Пользователь, который работает с дашбордом (в том числе только читает и двигает мышью), не теряет сеанс по правилу бездействия.
- **SC-003**: Несохранённые изменения при автоматическом выходе не теряются.
- **SC-004**: Без заданных правил ни один существующий сценарий входа и работы не меняется.

## Assumptions

- Варианты времени фиксированные (список выше) — этого достаточно и не требует проверки произвольных чисел.
- Предупреждение за 60 секунд; при правиле 15 минут это заметная, но не навязчивая доля времени.
- Кнопка «завершить все чужие сеансы» в этот объём не входит: правила и так действуют на открытые сеансы.
