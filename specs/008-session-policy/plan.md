# Implementation Plan: правила сеансов (spec 008)

**Spec**: [spec.md](spec.md) · **Date**: 2026-09-21 · **Migrations**: `003_app_settings.sql` · **Новые зависимости**: нет

## Design decisions

- **D1 — решает сервер.** Оба правила проверяются в `resolveSession()` при каждом запросе: `maxDays` — от `created_at`, `idleMinutes` — от последней активности. Нарушивший сеанс удаляется из базы; браузерная часть — только удобство (предупреждение, сохранение, понятная причина), обойти правило из браузера нельзя.
- **D2 — общие настройки приложения** — новая таблица `app_settings (key, value jsonb, updated_at, updated_by)`; ключ `session_policy`. Значения только из фиксированных списков (`IDLE_OPTIONS`, `MAX_DAYS_OPTIONS`), чтение кэшируется на 30 с — правило нужно на каждом запросе, а базу ради этого будить нельзя. Ошибка чтения не выкидывает людей: берётся последнее известное значение.
- **D3 — активность и экономия записей.** Активность — любой запрос с действующим сеансом. «Последняя активность» живёт в памяти процесса и пишется в базу не чаще раза в минуту и только при включённом правиле бездействия: без правил поведение и нагрузка на базу прежние (FR-007). После перезапуска сервера решает запись в базе (точность — минута, SC-001).
- **D4 — причина окончания.** Сервер 10 минут помнит, почему закончился сеанс с данным токеном (`idle` / `max`), и отдаёт это в ответе 401; приложение ведёт на `login.html?reason=…`, страница входа объясняет причину.
- **D5 — браузер** (`public/js/idle.js`): события мыши, клавиатуры, касаний и прокрутки; метка активности общая для вкладок через `localStorage`; сверка с сервером (`GET /api/auth/me`) не чаще раза в минуту и только если была активность — так сервер узнаёт, что человек читает дашборд; за 60 с до выхода — диалог с отсчётом («Остаться» / «Выйти сейчас», Esc = остаться); при выходе — `saveNow()` → `POST /api/auth/logout` → страница входа; остальные вкладки уходят по событию `storage`. Правило приходит в `/api/auth/me` и обновляется при каждой сверке.
- **D6 — интерфейс администратора**: блок «Сеансы» в «Настройках» над «Пользователями» (виден только администратору), два списка, сохранение по выбору, подпись «кто и когда менял». Маршруты `GET/PUT /api/admin/session-policy` — только admin, с защитой от CSRF; изменение пишется в журнал сервера.
- **D7 — фоновые задачи** не затрагиваются: задача принадлежит серверу и дописывает результат в анализ после выхода пользователя.
