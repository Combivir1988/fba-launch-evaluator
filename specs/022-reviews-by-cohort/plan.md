**Spec**: [spec.md](./spec.md)
**Created**: 2026-11-14
**Status**: Ready for `/speckit.tasks`

## Technical Context

Стек прежний: Node 22 + Express 5, vanilla ES modules без сборки, чистое ядро в `shared/` — общее для браузера и `node --test`. **Новых зависимостей нет. Миграции нет**: все три величины считаются на лету, ничего не хранится.

Работа целиком внутри расчётного ядра и текстов интерфейса. Новых данных не требуется — всё, что нужно, уже посчитано и лежит рядом.

### Факт, который определил устройство плана

Порядок в `shared/compute.js`:

| Строка | Что считается |
|---|---|
| 41 | `competition` — здесь уровень рва из отзывов лидера |
| 48 | `criterion1` — здесь подпункт «Отзывы по нише» |
| **78** | `entry` — **только здесь появляется когорта новичков** |
| 92 | `scorecard` — читает уровень рва |

Поток идёт `competition → entry`: строка 78 передаёт в `entryFeasibility` поля из `competition`. Обратный поток создал бы цикл, поэтому «передать когорту в competition» нельзя.

**Решение (D4)**: порядок не меняем. `competition.reviewBarrier` остаётся сырым фактом о лидере; **действующий** уровень считается после `entry` и дописывается отдельным полем с указанием основания. Scorecard (строка 92) видит когорту и читает действующий уровень.

## Порядок работ

**1. Базовый замер — ПЕРВОЙ задачей, до единой правки в `shared/`.** `method_hash` — sha256 по содержимому всех `shared/*.js`; первая правка стирает прежние цифры. Снять вердикты, статусы подпунктов, число зелёных и уровни рва по всем живым анализам в фикстуру **без названий ниш**.

**2. Ворота SC-001 тестом, до реализации.** Статус подпункта по медиане. Обязан падать на расчёте по среднему — проверить подстановкой.

**3. Ворота SC-002 тестом, до реализации.** Действующий уровень барьера из когорты. Обязан падать на расчёте по лидеру — проверить подстановкой.

**4. Подпункт «Отзывы по нише» на медиану.** Плюс `borderline.js` (D7) и пейлоады (D8) — в той же задаче, иначе в отчёте окажутся две меры одного подпункта.

**5. Действующий уровень барьера.** Медиана отзывов когорты наружу из `entry`; пересчёт уровня в `compute.js` после строки 78; `scorecard.js` на действующий уровень. Сырой уровень не трогать.

**6. Доля с отзывом из когорты.** Считается один раз в `compute.js`, передаётся и в `entry`, и в `cashflow`. Отбрасывание невозможного, медиана, потолок из порогов.

**7. Ворота SC-003.** Контрольный отпечаток на фикстуре, где медиана и среднее дают один статус. Фикстуры может не быть — тогда сделать.

**8. Тексты, подсказки, Справка.** Показатель, сменивший смысл, не может сохранить прежнее объяснение.

**9. Живая проверка после развёртывания** — проверка 9 из quickstart, со сверкой по базовому замеру.

**MVP = пункты 1–7.** Без текстов работа не считается сделанной (пункт 8 обязателен к выпуску), но считать она уже будет верно.

## Риски

| Риск | Что делаем |
|---|---|
| Смена меры в 1d потянет за собой места, о которых не подумали | `borderline.js` и пейлоады правятся в той же задаче; контрольный отпечаток покажет остальное |
| Пересчёт уровня барьера заденет Критерий 5 | Критерий 5 читает `top5Share`, не `reviewBarrier`; проверяется тестом на неизменность |
| Доля с отзывом разойдётся между двумя потребителями | считается один раз и передаётся контекстом (D6) |
| Живые числа разойдутся с ожиданием из замера | расхождение — повод остановиться, а не поправить ожидание (quickstart, проверка 9) |
