# Implementation Plan: бренд против куска слова

**Spec**: [spec.md](./spec.md) · **Branch**: `main` · **Created**: 2026-11-14
**Артефакты**: [research.md](./research.md) (D1–D10) · [data-model.md](./data-model.md) · [contracts/matching.md](./contracts/matching.md) · [quickstart.md](./quickstart.md)

## Technical Context

Стек прежний: Node 22 + Express 5, vanilla ES modules без сборки, чистое расчётное ядро в `shared/`, общее для браузера и `node --test`. **Новых зависимостей нет. Миграции нет. Нового хранения нет.**

Правка лежит в расчётном ядре, поэтому признак версии методики сменится и раздел «Статистика» один раз пересчитается целиком (по прежним замерам около 20 секунд). Это ожидаемое следствие, а не поломка.

## Два факта, которых не было в спеке

**Первый: мест с подстрочным совпадением два, а не одно.** Кроме разметки фраз, своя подстрочная проверка есть в расчёте лояльности к бренду, а он кормит подпункт Критерия 5, который влияет на вердикт. Значит работа **не чисто добавочная**, и контрольный отпечаток сдвинется. Замер двумя отдельными процессами показал границу этого влияния: **вердикт не меняется ни у одного из 69 анализов**, число зелёных в Критерии 5 — тоже ни у одного, меняется только статус одного подпункта (`warn → ok`). Решение — перевести лояльность на общий матчер (D4): два правила «что такое брендовый запрос» разойдутся при первой же правке.

**Второй: переразметка при открытии уже есть, но она только вычитает.** Открытие анализа переразмечает сохранённые фразы текущим правилом, но с кластером делает ровно одно действие — **удаляет** ставшие брендовыми. Обратной операции нет, поэтому после починки сохранённый разбор останется с прежними восемью фразами. История US3 остаётся обязательной (D6).

## Ключевые решения

Полностью — в [research.md](./research.md). Коротко:

| № | Решение | Главное основание |
|---|---|---|
| **D1** | Совпадение: цепочкой слов **или** слитной записью многословного имени | Половина всей разметки ложная (4 899 из 9 942), а цена перехода — 83 фразы, и правило их сохраняет |
| **D2** | **Нижнюю границу длины не вводим** | Замер опроверг ожидание: по слову трёхбуквенные имена дают `giro helmet`, `met helmet`, `hjc helmet` — настоящие марки |
| **D3** | Ключ анализа защищается, хотя сегодня правило не срабатывает (0 из 67) | Самопроверяемый инвариант: будь он раньше, ошибка закричала бы сразу |
| **D4** | Лояльность — на общий матчер | Вердикт не двигается (0 из 69); две копии правила разойдутся |
| **D5** | Отпечаток сдвинется у одного анализа — названо заранее | Иначе при расхождении обновят число вместо разбирательства |
| **D6** | Сохранённый кластер: **добавить недостающее**, не пересобирать | Пересборка затрёт ручной выбор, и восстановить его нельзя |
| **D7** | Планка близости — **главное слово ключа**, со ступенями смягчения | Отсекает ровно те шесть фраз, на которые пожаловался человек, и сохраняет весь центр ниши |
| **D8** | Порядок US1+US2 → US3 → US4 | До починки брендов пул для замера планки пуст |
| **D9** | Базовый замер первой задачей | Признак версии методики стирает прежние цифры |
| **D10** | Миграции нет | Нечего хранить |

## Порядок работ

### 1. Базовый замер — ПЕРВОЙ ЗАДАЧЕЙ, до единой правки в ядре

Чтением живой базы **без единой записи**: вердикт, статусы подпунктов Критерия 1, статус и значение подпункта «Лояльность к бренду», статус блока трафика, число релевантных, число групп, доля топ-2, размер кластера, число брендовых фраз. Фикстура **без названий ниш**.

Первая правка в `shared/` пересчитает сохранённые итоги текущим кодом, и сравнивать станет не с чем.

### 2. Ворота SC-001 и SC-002 — тестами, ДО реализации

Контрольные значения — из [contracts/matching.md](./contracts/matching.md). Оба проверяются подстановкой, и SC-001 обязан падать **на пунктах про `helmet`, а не на пунктах про `met helmet`**: если падает везде, задето больше, чем задумано.

### 3. Правило совпадения (US1, US2)

Подстрочная проверка заменяется на две проверки по границе слова — цепочкой слов и слитной записью. Защита ключа анализа распространяется на полные имена. Разметка ставится в двух местах (при разборе выгрузки и при смене ключа или списка брендов), оба используют один матчер — тест обязан это закрепить, иначе при следующей правке они разойдутся.

### 4. Лояльность к бренду — на общий матчер (US1)

Собственная подстрочная проверка убирается. Ожидаемые числа — из [data-model.md](./data-model.md); расхождение с ними означает, что сделано не то.

### 5. Инвариант сужения (SC-003)

Проверка на всех живых данных: ни одна фраза не получила признак брендовой, которого не имела. Ожидание — ноль нарушений.

### 6. Сохранённый кластер (US3)

Расхождение считается сравнением на лету: фраза была брендовой по прежнему правилу, перестала по новому и проходит отбор. Показывается числом; действие «добавить» вносит только эти фразы. Открытие анализа **ничего не меняет** до нажатия. Попадает в историю версий.

### 7. Планка смысловой близости (US4)

Главное слово ключа, со ступенями смягчения: главное слово → половина слов → любое слово. Применённая ступень называется человеку — так же, как уже называется смягчение отбора по силе конкурентов. Делается **после** пунктов 3–6, чтобы эффект был измерим отдельно.

### 8. Тексты, подсказки, Справка

Подпись про скрытые брендовые фразы перестаёт быть нейтральной отчётностью и говорит, по какому правилу идёт отбор. Карточка в Справке: что стало считаться иначе, почему, и к чему это привело на живых данных. `tests/tips.test.js` обязан остаться зелёным.

### 9. Живая проверка после развёртывания

Проверка 9 из [quickstart.md](./quickstart.md), со сверкой по базовому замеру. Ожидания занесены как условие приёмки.

**MVP = пункты 1–6.** Без пункта 7 работа уже чинит главное: ниша перестаёт исчезать. Без пункта 8 не выпускается.

## Особо про замеры

Если понадобится мерить подстановкой в ядро — **только двумя отдельными процессами**. Внутри одного процесса модули берутся из кэша, подстановка не подхватывается и замер даёт **ложный ноль**. Это уже случалось при планировании спеки 022 и чуть не определило её целиком. Замер D4 в этой работе сделан правильно — двумя запусками с восстановлением файла между ними.

## Риски

| Риск | Что с ним |
|---|---|
| Планка «главное слово» голодает в 17 нишах из 67 | Закрыто ступенями (D7); ступень называется человеку |
| Имя бренда совпадает со словом ниши (`bell`, `out`) | Остаётся; масштаб замерен — около 151 фразы на 67 анализов против 4 899 исправляемых. В Справке сказано, что марку можно исключить вручную |
| Отпечаток сдвинулся шире ожидаемого | Повод остановиться: ожидаемый сдвиг назван заранее (D5) |
| Сохранённые кластеры остаются неполными | Закрыто US3; молчание здесь равносильно тому, что работа не сделана |

## Вне зоны

Значения порогов блока «Трафик по ключам» (замерено — различают); ступени отбора по силе конкурентов; нижняя граница длины имени бренда и расширение стоп-списка (D2, обосновано замером); качество самой выгрузки; смысловая кластеризация моделью; зеркало в saas.
