**Spec**: [spec.md](./spec.md) · **Plan**: [plan.md](./plan.md) · **Контракт**: [contracts/matching.md](./contracts/matching.md) · **Приёмка**: [quickstart.md](./quickstart.md)

Миграции нет. Нового хранения нет. Новых зависимостей нет. Новых порогов нет.

**Срочность (2026-11-16)**: ошибка не просто портит отчёт — она **уничтожает ручную работу**. Человек отобрал 135 фраз, они сохранились верно (135 в базе), но при каждом открытии анализа все 135 помечаются брендовыми и **выбрасываются из кластера** (проверено подсчётом: «сохранено 135 → остаётся 0»). База цела только потому, что открытие само по себе не пишет; первая же правка сохранит пустой кластер. Фаза 3 — это и есть лечение.

## Dependencies

```
Phase 1 (T001–T002)  ← ДО любой правки в shared/
      ↓
Phase 2 (T003–T006)  ← ворота пишутся до реализации
      ↓
Phase 3 US1 (T007–T014)  ← MVP, лечит потерю данных
      ↓
Phase 4 US2 (T015–T018)  ← опирается на новый матчер
      ↓
Phase 5 US3 (T019–T024)  ← нужно новое правило, чтобы считать расхождение
      ↓
Phase 6 US4 (T025–T030)  ← после US1, иначе пул для замера пуст
      ↓
Phase 7 (T031–T035)
```

**Почему порядок не произволен**: до починки правила в нише шлемов годных фраз с главным словом **ноль**, поэтому любой замер планки близости (US4) до US1 даст бессмыслицу. US3 считает расхождение сравнением прежнего и нового правила — значит новое правило должно существовать.

## Implementation strategy

**MVP = Phases 1–5 (T001–T024).** После них приложение перестаёт уничтожать ручной выбор и перестаёт лгать о нише; испорченные кластеры восстанавливаются одним действием.

**Phase 6 (US4)** — отдельный выпуск: его эффект обязан быть измерим отдельно от эффекта US1.

**Без Phase 7 не выпускается**: показатель, сменивший смысл, не может сохранить прежнее объяснение.
