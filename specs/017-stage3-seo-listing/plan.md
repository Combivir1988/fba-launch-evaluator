# Implementation Plan: этап 3 — SEO-листинг и аудит своего (spec 017)

**Spec**: [spec.md](spec.md) · **Date**: 2026-10-27 · **Migrations**: нет (всё в `core` анализа) · **Новые зависимости**: нет

## Design decisions

- **D1 — Целевые ключи** `shared/keywords-target.js` → `targetKeywords({ cerebro, poe, sqp, inputs, th })`. Объединение по нормализованной фразе (нижний регистр, схлопнутые пробелы): Cerebro даёт `sv` и признаки `isBranded`/`isAsin`, POE — `svT360` (делим на 12, когда Cerebro нет) и `clickShareT360`, SQP — `impressions/clicks/purchases`. Вес ключа = `sv` Cerebro, иначе месячный POE. Признак **`buys`** — в SQP по этому запросу есть покупки; **`trafficOnly`** — показы и клики есть, покупок нет. Брендовые фразы и ASIN-фразы исключаются (они не наши). Сортировка: сначала `buys` по весу, затем остальные по весу; берём `th.stage3.topKeywords` (50). Без Cerebro работает на POE/SQP с пометкой «объёмов поиска нет».

- **D2 — Матрица покрытия** `shared/listing-coverage.js` → `coverage({ keywords, listings, own, th })`. Токенизация: нижний регистр, долой пунктуацию, простое множественное число (`s$` при длине > 3), англ. стоп-слова (список в ядре). Ключ считается покрытым в поле, если **все его значимые токены** есть в токенах поля — порядок не важен, Amazon индексирует слова, а не фразу. Считаем отдельно `title`, `bullets`, `specs` по каждому листингу из кэша этапа 2 (`aggregates.listings`), новых загрузок не нужно. На выходе по ключу: сколько конкурентов держат его в тайтле/буллетах/характеристиках и доля; **`mustHave`** — доля в тайтлах ≥ `th.stage3.mustHaveShare` (0.6); **`whiteSpace`** — доля в тайтлах ≤ `whiteSpaceShare` (0.05) при весе выше медианы. Та же функция считает покрытие моего листинга, когда его страница есть.

- **D3 — Оценка текста** `shared/listing-score.js` → `scoreListing({ listing, keywords, bans, th })`, чистая и синхронная: пересчёт на каждую правку в браузере, без сервера. Даёт: покрытие ключей **в штуках и в весе** (отдельно по полям и суммарно), длины всех полей против лимитов (**backend terms меряем в БАЙТАХ UTF-8**, остальное в знаках), повторы слов между backend и тайтлом/буллетами (они тратят байты впустую), найденные запрещённые утверждения. `bans` собираются детерминированно из патентного скана (патенты с риском `high`/`med` → их `claimed` как запретные обещания) и регуляторных триггеров (spec 005).

- **D4 — AI пишет только текст.** Новая фоновая задача `listing_draft` (`server/listing-jobs.js`, схема и промпт в `server/listing-prompts.js`), через `openrouterJson` со строгой схемой `LISTING_SCHEMA` = `{ title, highlights, bullets[5], description, backendTerms }`. На вход идут готовые факты: целевые ключи с пометками `mustHave`/`whiteSpace`/`buys`, доминирующая конфигурация и ★ премиальные значения этапа 2, ценовой ориентир (spec 013), темы негативных отзывов POE, запреты из D3 и лимиты. Промпт — по-русски, **текст листинга — английский** (это листинг для Amazon US); модель не придумывает фактов и не обещает запрещённое. Оценку текста считаем сами (D3), модели не доверяем.

- **D5 — Аудит своего листинга.** Задача `listing_audit`: берёт ASIN из `inputs.myAsins` (если их несколько — выбор в интерфейсе), грузит страницу через существующий `fetchMany` (кэш 30 дней, та же цена ≈ 30 кредитов, только по кнопке с подтверждением), считает `coverage.own` и список исправлений **без AI**: непокрытые ключи по убыванию веса, у каждого — место правки (в тайтл, если ключ короткий и в 75 знаках есть место; иначе в буллеты; если ключ совпадает с полем схемы этапа 2 — в характеристики) и прирост покрытия в объёмах поиска. Повторная проверка берёт страницу из кэша, пока не нажата «Загрузить заново».

- **D6 — Хранение и граница наружу.** `core.listing = { draft: {…}, editedAt, model, audit: { asin, fetchedAt, fixes } }`; вычисляемое — `results.stage3` (ключи, покрытие, оценка). **В снимок публичной ссылки и в автономный HTML не попадает ничего из этапа 3**: `buildSnapshot` удаляет и `core.listing`, и `results.stage3` (по образцу `config.tz` и закупочной экономики из spec 002) — данных нет в файле, а не спрятаны при показе. Проверяет тест-ловушка `findStage3Leaks` по образцу `findEconomicsLeaks`. `results.stage3` добавляется в `stripNew` контрольных отпечатков.

- **D7 — Третья вкладка.** `STAGE3 = new Set(["keywords", "listing", "audit"])`, `stageOf` расширяется до 3, `stageTabsHtml` рисует третью вкладку **только когда `o.static !== true`** — в снимке и в скачанном HTML её нет вовсе. Вкладка доступна, когда есть хоть один источник ключей (Cerebro / POE / SQP); без страниц этапа 2 показывает ключи и честно пишет, что матрицы покрытия не будет.

- **D8 — Пороги** (вкладка «Пороги», группа «Этап 3 — листинг»): `stage3 = { topKeywords: 50, mustHaveShare: 0.6, whiteSpaceShare: 0.05, titleMax: 75, highlightsMax: 125, bulletMax: 500, backendBytes: 250 }`. Лимиты вынесены в пороги намеренно: правила Amazon меняются, и это не повод править код.

- **D9 — Отдать в работу.** Правка полей прямо в таблице (как ТЗ), кнопка «скопировать» у каждого поля (`navigator.clipboard`, запасной путь через скрытое поле — на случай http), «Скачать TXT» одним файлом. DOCX не делаем: листинг вставляют в Seller Central по полям, а не печатают.

## Порядок работ

1. Ядро и тесты: `keywords-target.js`, `listing-coverage.js`, `listing-score.js` (чистые функции на фикстурах — быстрее и надёжнее, чем через интерфейс).
2. `compute()` → `results.stage3`; `stripNew`; снимок и `findStage3Leaks`.
3. Вкладка: карта ключей и матрица (US1) — она же проверяет ядро глазами.
4. Задача `listing_draft` + таблица правки + оценка (US2, US3, US5).
5. Задача `listing_audit` (US4).
6. Справка, подсказки, проба Playwright.

## Риски и готчи

- **Лимит backend terms — в байтах**, не в знаках: кириллицы там не будет, но длинные слова и запятые считаются иначе; меряем `Buffer.byteLength`/`TextEncoder`.
- **Покрытие по токенам, а не по фразам** — иначе почти всё выглядит «непокрытым». В интерфейсе это надо сказать словами, иначе будут вопросы, почему ключ засчитан.
- **Страницы этапа 2 — это текст конкурентов на момент загрузки**; если кэш старый, матрица покрытия устарела. Показываем дату.
- **Свой ASIN может быть не в нише** (другой товар) — предупреждаем, но не запрещаем.
- **Задача `listing_draft` не должна становиться «зелёным» фактом**: это текст, а не расчёт. В критерии и вердикт этап 3 не влияет вообще.
