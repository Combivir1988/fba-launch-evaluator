# Feature Specification: FBA Launch Evaluator (веб-приложение)

**Feature Branch**: `001-fba-launch-evaluator` · **Created**: 2026-09-17 · **Status**: Draft
**Input**: Веб-приложение, воспроизводящее скилл `fba-launch-evaluator` (оценка ниши/товара для запуска на Amazon FBA, Go / Go условно / Доработка / No-Go) с русским интерфейсом, AI-синтезом через Claude, интерактивным дашбордом (графики, поля, ползунки), скачиванием дашборда и историей анализов; бесплатный хостинг; отдельный проект `fba-launch-evaluator/`.

## Проблема

Сегодня оценка ниши делается вручную через чат-скилл: пользователь присылает экспорты Helium 10 (Xray, Cerebro), опционально POE JSON и SQP, ассистент считает Критерий 1 (1a–1h), гейты экономики, критерии 3–8, собирает Excel и HTML-дашборд. Процесс не воспроизводим (каждый раз новая беседа), цифры нельзя «покрутить» (изменил COGS — пересчёт только через новый запрос), результаты не накапливаются в одном месте, а поля Excel для экономики заполняются вручную. Нужен инструмент, который даёт тот же результат, что скилл, но: детерминированные расчёты выполняются мгновенно и локально, AI используется только для синтеза (вердикт, аргументация, рекомендации), а история и экспорт встроены.

Источники методологии: `fba-launch-evaluator/SKILL.md` (Критерий 1, критерии 2–8, шкалы, гейты, правила сверки источников) и курс «Выбор товара на Amazon» (уроки 03–14: категории/сертификаты, четыре стоп-вопроса урока 07, бюджет первой закупки урока 08, распределение трафика и жизненный цикл урока 09, советы по ROI/цене урока 10, метрики POE и концентрация кликов урока 11, тест дизайна урока 12, патенты/ТМ урока 13, склейка отзывов урока 14).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Оценить нишу по файлам и получить вердикт (Priority: P1)

Пользователь вводит название ниши / главный ключ, загружает Xray CSV и Cerebro CSV (опционально POE JSON и SQP CSV), отмечает релевантные ключи кластера, нажимает «Рассчитать». Приложение мгновенно показывает дашборд: KPI-плитки, таблицу-гейт Критерия 1 (1a–1h) со статусами OK / погранично / НЕ OK и итогом «X из 8», концентрацию брендов, барьер отзывов, распределение трафика, сезонность (если есть POE trends). Затем пользователь нажимает «AI-анализ» — приложение отправляет агрегированные метрики (не сырые файлы) в Claude и получает структурированный вердикт: Go / Go условно / Доработка / No-Go, какой гейт решающий, обоснование по каждому критерию, 3 следующих шага, гипотезы дифференциации из отзывов.

**Why this priority**: это ядро скилла — без него приложение не имеет ценности. Даже без AI детерминированный дашборд уже заменяет ручную сборку Excel.

**Independent Test**: загрузить реальные `Helium_10_Xray_2026-08-21.csv` + `US_AMAZON_cerebro__2026-08-21.csv` и `POE_urinal_screen_deodorizer_2026-09-15.json`; убедиться, что Niche Revenue, средняя цена (медиана по листингам с ≥100 отзывов), Adj. SV, Top Brand Share, Top-5 Brand Share совпадают с ручным расчётом по формулам скилла с точностью до округления; AI-блок содержит все обязательные поля.

**Acceptance Scenarios**:

1. **Given** загружен Xray CSV с европейским форматом чисел («69,95», «6 892» с неразрывным пробелом) и дублями ASIN, **When** пользователь нажимает «Рассчитать», **Then** суммы посчитаны корректно (запятая → десятичная точка, пробел-разделитель убран), дубли ASIN учтены один раз, вариации (строки «3.1.», «3.2.») не задваивают Parent Level Revenue.
2. **Given** загружен только POE JSON (без Xray/Cerebro), **When** расчёт, **Then** 1a и 1c посчитаны по прокси-формулам POE и явно помечены «прокси POE — требует сверки по Xray/Cerebro»; Gate 0 = «недостаточно данных для точных Gate 1–2», но Критерий 1 и дашборд построены.
3. **Given** Критерий 1 даёт 5 из 8 зелёных, а 1b — пограничный (жёлтый), **When** отображается итог, **Then** жёлтый не засчитан в «N из 8», статус «НИЖЕ ПОРОГА» показан как предупреждение и учтён в финальном вердикте.
4. **Given** Top Brand Revenue Share > 25 %, **When** расчёт, **Then** блок критериев 3–8 активируется автоматически, критерии 6 и 8 помечены как обязательные.
5. **Given** пользователь нажал «AI-анализ», **When** ответ получен, **Then** вердикт согласован с гейтами (например, AI не может выдать «Go» при проваленном Gate 2), а каждое утверждение AI ссылается на конкретную метрику дашборда.
6. **Given** Xray и POE загружены, а после — новый Xray для той же ниши, **When** пересчёт, **Then** 1a/1c/1f пересчитаны по Xray/Cerebro, и показана разница с прежней POE-прокси оценкой.

### User Story 2 — Живая экономика и бюджет через ползунки (Priority: P1)

Пользователь задаёт цену продажи, COGS, доставку, комиссию Amazon (referral %), FBA-сбор, CPC, доли PPC/органика и двигает ползунки CVR (8–15 %), ACOS, цену. Дашборд мгновенно пересчитывает Gate 1 (маржа, профит/юнит), Gate 2 (Net after ads при CVR 8/10/12/15 %), ROI, маржинальность с рекламой и без (два числа рядом, как требует скилл), а также калькулятор бюджета первой закупки (урок 08: COGS × шт/день × (производство + доставка + 15 дней приёмки) × 2 партии + резерв на рекламу) и четыре стоп-вопроса урока 07. Всё без обращения к AI.

**Why this priority**: Gate 2 (стресс-тест рекламы) — «самый часто пропускаемый шаг» скилла и главная причина краха товаров (урок Jitsu). Интерактивность — явное требование пользователя.

**Independent Test**: ввести пример Jitsu 12-pack ($23.90, COGS такой, что маржа 46 %) и 48-pack ($42.99, маржа 35.6 %) с одинаковым CPC — приложение должно показать, что 12-pack проваливает Gate 2, а 48-pack проходит.

**Acceptance Scenarios**:

1. **Given** заполнены цена/COGS/сборы/CPC, **When** пользователь двигает ползунок CVR, **Then** график «Net after ads vs CVR» и статус Gate 2 обновляются не позже чем через 100 мс, без сетевых запросов.
2. **Given** COGS не введён, **When** открыт дашборд, **Then** Критерий 2 (2a–2k) и критерий 6 показаны как «⚪ ожидает данных менеджера», Gate 1–2 = «прикидка», не гейт; AI не заполняет их сам.
3. **Given** цена < $25, **When** расчёт Gate 1, **Then** применяется поправка дешёвого сегмента (только % маржи > 30 %, абсолютный порог $15 не применяется) с явной пометкой.
4. **Given** заданы бюджет, COGS, шт/день, сроки производства и доставки, **When** расчёт бюджета, **Then** показаны суммы первой и второй партии, дефицит/запас относительно бюджета и вывод стоп-вопроса «продукт не подходит для бюджета».
5. **Given** ROI > 200 %, **When** отображение, **Then** предупреждение «перепроверь данные» (урок 10); ROI < 100 % — «убыток»; ROI 100–150 % — «ниже порога 150 %».

### User Story 3 — История анализов и экспорт (Priority: P2)

Каждый рассчитанный анализ сохраняется в историю (название ниши, дата, вердикт, Критерий 1 X/8, итоговый %). Пользователь открывает историю, загружает любой анализ обратно в дашборд со всеми входными переменными и AI-ответом, удаляет ненужные, экспортирует всю историю или один анализ в файл и импортирует обратно на другом устройстве. Дашборд скачивается как автономный HTML-файл (открывается офлайн, содержит графики и данные) и как JSON.

**Why this priority**: пользователь явно требует историю и скачивание; без них приложение — одноразовый калькулятор.

**Independent Test**: сделать анализ, перезагрузить страницу, открыть из истории — все поля, ползунки, статусы и AI-ответ восстановлены; скачанный HTML открывается без интернета и показывает те же цифры.

**Acceptance Scenarios**:

1. **Given** выполнен анализ, **When** страница перезагружена, **Then** анализ виден в списке истории с датой и вердиктом.
2. **Given** пользователь загрузил анализ из истории и изменил ползунок, **When** нажал «Сохранить», **Then** создаётся новая версия (старая не перезаписывается молча) либо явно перезаписывается по подтверждению.
3. **Given** экспортированный файл истории, **When** импорт на чистом браузере, **Then** список восстановлен полностью, дубликаты (одинаковый идентификатор) не задваиваются.
4. **Given** дашборд на экране, **When** «Скачать HTML», **Then** файл содержит все секции дашборда, графики отрисованы без внешних запросов, в имени файла — ниша и дата.

### User Story 4 — Чеклист рисков: compliance, IP, серые схемы, дифференциация (Priority: P3)

Пользователь проходит чеклист, взятый из курса: закрытая ли категория, опасные товары, нужные сертификаты (CPC/FDA/Prop 65), проверка USPTO/Google Patents/WIPO, признаки склейки отзывов у конкурентов, доля листингов с купонами/дилами, наличие Amazon как продавца, результат теста дизайна (PickFu ≥ 30–50 %), жизненный цикл > 25 мес. Ответы влияют на ось «Operational Risk» и на критерии 7–8 (статусы 🟢 подтверждено / 🟡 допущение / 🔵 решено / ⚪ не проверено).

**Why this priority**: закрывает Gate 4 и уроки 03/04/13/14, но не блокирует основную ценность.

**Independent Test**: отметить «патент — прямое совпадение» — критерий 8 красный, итоговый вердикт не может быть «Go».

**Acceptance Scenarios**:

1. **Given** чеклист не заполнен, **When** расчёт, **Then** критерии 7–8 = ⚪ и в вердикте явно «Gate 4 не обсуждён».
2. **Given** отмечено «Amazon продаёт сам в нише», **When** расчёт 1e, **Then** 1e = НЕ OK независимо от Top Brand Share.

---

### Edge Cases

- Xray CSV без колонки `ASIN Sales` (старый экспорт) — использовать `Recent Purchases` только для грубой фильтрации и пометить, что точные медианы недоступны.
- Cerebro содержит ASIN-строки («b0751cbxbt») и брендовые запросы — исключаются из кластера автоматически (ASIN по маске, бренды из списка брендов Xray) с возможностью вернуть вручную.
- Cross-category contamination: бренд из Xray отсутствует в POE `asinMetrics` — подсветить как подозрительный и дать переключатель исключения из агрегатов.
- POE `trendsMetrics` пуст или содержит < 8 недель — сезонность 1g «недостаточно истории», не «НЕ OK».
- Ответ AI не парсится / не полный / сервис недоступен — дашборд остаётся полностью функциональным, показан понятный статус ошибки и кнопка повтора; расчёты не зависят от AI.
- Файл больше лимита (например Cerebro на 50 000 строк) — обработка не блокирует интерфейс, показан прогресс.
- Пользователь — действующий владелец бренда в нише: флаг «мой ASIN/бренд» подсвечивает строку в конкурентах, но при оценке «нового входа» бренд считается инкумбентом.
- Расхождение источников > 30 % (Xray vs POE) — не усреднять, показать оба числа и причину-подсказку.

## Requirements *(mandatory)*

### Functional Requirements

**Ввод и разбор данных**

- **FR-001**: Система MUST принимать название ниши / главный ключ и файлы: Helium 10 Xray CSV (обязательно для точных Gate), Cerebro CSV (обязательно для 1c), POE JSON schemaVersion 1 (опционально), SQP CSV (опционально); файлы разбираются на стороне пользователя и не покидают браузер целиком.
- **FR-002**: Разбор Xray MUST учитывать: BOM, десятичную запятую, неразрывный пробел как разделитель тысяч, дубликаты ASIN, иерархию вариаций (Parent Level vs ASIN), даты «Aug 22, 2017», значения «N/A» и «>100,000».
- **FR-003**: Система MUST позволять пользователю отметить релевантные ключи кластера из Cerebro (по умолчанию — автопредложение по совпадению слов с главным ключом, исключая ASIN-строки и брендовые запросы) и рассчитывать `Adj. SV = SV core + 0.4 × Σ SV остальных`.
- **FR-004**: Система MUST давать возможность вручную ввести/переопределить любую метрику Критерия 1, если файла-источника нет, с пометкой «введено вручную».

**Детерминированные расчёты**

- **FR-005**: Система MUST рассчитывать Критерий 1 (1a Niche Revenue ≥ $500k/мес; 1b цена ≥ $30 OK, $25–30 погранично, < $25 НЕ OK; 1c Adj. SV ≥ 3 000; 1d среднее/медиана отзывов < 300 OK, > 1000 НЕ OK; 1e Top Brand Share < 25 % и нет Amazon-продавца; 1f Top-5 брендов < 45 % OK, > 65 % НЕ OK; 1g просадка сезонности < 30 % OK, > 50 % НЕ OK; 1h успешность запусков ≥ 30 % OK, < 10 % НЕ OK) с итогом «N из 8», где в счёт идут только чёткие OK; порог прохождения — 6.
- **FR-006**: Для 1a/1c без Xray/Cerebro система MUST использовать прокси POE (units × avgPrice / 12; searchVolumeT360 / 12 по кластеру) с явной пометкой «прокси», а при появлении Xray/Cerebro — пересчитывать и показывать расхождение.
- **FR-007**: Система MUST рассчитывать Gate 1 (маржа > 30 % И (профит > $15 ИЛИ маржа > 40 % для товаров < $25)) и Gate 2 (`Ad cost = CPC / CVR`, `Net after ads = Net − Ad cost × доля PPC` при CVR 8/10/12/15 %) со статусами PASS / ДОРАБОТКА / NO-GO по правилам скилла; показывать маржу без рекламы и с рекламой рядом.
- **FR-008**: Критерий 2 (2a–2k) и критерий 6 MUST оставаться «⚪ ожидает данных» до ввода менеджером COGS и остальных переменных; заполняются только из введённых чисел, никогда из AI.
- **FR-009**: Система MUST активировать критерии 3–8 при Top Brand Share > 25 % и считать итог «N из 8 (Критерий 1 + 3–8)» с обязательными зелёными 6 и 8; статусы 🟢/🟡/🔵/⚪ различаются, в порог идут только 🟢.
- **FR-010**: Система MUST рассчитывать 5-осевой scorecard (Market 25 %, Competition 25 %, Economics 25 %, Brand-fit 15 %, Operational Risk 10 %) с итоговым % и порогами 80/60/40 и показывать, какая ось слабая.
- **FR-011**: Система MUST рассчитывать четыре стоп-вопроса урока 07 (бюджет vs COGS, ROI ≥ 150 %, выручка первой страницы ≥ $500k/мес, возможность дифференциации — отметка пользователя) и бюджет первой закупки урока 08 (две партии + резерв).
- **FR-012**: Система MUST рассчитывать распределение трафика по ключам (доля SV топ-2 ключей, число групп, число релевантных ключей ≥ 30) по уроку 09 и концентрацию кликов по POE (`top5/top20 brands/products click share`, `sponsoredProductsPercentage`, `searchConversionRate` < 1 % = неудовлетворённый спрос) по уроку 11.
- **FR-013**: Все пересчёты по изменению полей и ползунков MUST выполняться мгновенно локально, без сетевых запросов и без повторного AI-вызова.

**AI-синтез**

- **FR-014**: Система MUST по нажатию кнопки отправлять в Claude только агрегированные метрики, статусы гейтов, топ-N конкурентов, топ-N запросов и темы отзывов (не сырые файлы) и получать структурированный ответ: вердикт, решающий гейт, обоснование по критериям, 3 следующих шага, гипотезы дифференциации/ТЗ, риски, комментарий по комплектации/цене.
- **FR-015**: Вердикт AI MUST быть согласован с детерминированными гейтами: приложение валидирует ответ (не «Go» при проваленном Gate 1/2 или красном критерии 6/8) и при несоответствии показывает «AI-вердикт скорректирован правилами» с обоими значениями.
- **FR-016**: Ключ доступа к AI MUST храниться только на сервере (переменная окружения), никогда в браузере; доступ к приложению защищён паролем доступа (один общий пароль или токен), чтобы публичный бесплатный хостинг не позволял чужим тратить бюджет AI.
- **FR-017**: Система MUST показывать ход AI-анализа (потоковый вывод или индикатор) и понятную ошибку с кнопкой повтора; прекращение AI не ломает дашборд.

**Дашборд и экспорт**

- **FR-018**: Интерфейс MUST быть на русском языке; дашборд MUST содержать секции: обзор (KPI), Критерий 1 (таблица-гейт), экономика (Gate 1/2, график Net vs CVR), бюджет, конкуренты (бар-чарт click/revenue share + таблица топ-20), ценовые сегменты, запросы (таблица топ-20), сезонность/тренд (график по неделям, если есть POE), структура ниши (сейчас/квартал/год), тональность отзывов (diverging chart негатив/позитив), критерии 3–8, scorecard (радар), чеклист рисков, AI-вердикт и рекомендации.
- **FR-019**: Система MUST скачивать дашборд как автономный HTML (все данные и графики внутри, без внешних запросов) и как JSON; имя файла = ниша + дата.
- **FR-020**: Система MUST поддерживать светлую и тёмную тему и корректно работать на ширине от 360 px.

**История**

- **FR-021**: Система MUST сохранять каждый анализ (входные переменные, отмеченные ключи, агрегаты файлов, результаты расчётов, AI-ответ, дату) и показывать список истории с поиском по названию.
- **FR-022**: Пользователь MUST иметь возможность загрузить анализ из истории обратно в дашборд, удалить его, экспортировать один или всю историю в файл и импортировать файл обратно без дублей.
- **FR-023**: История MUST сохраняться между сессиями на устройстве пользователя без обязательной регистрации; хранение сырых файлов целиком — не требуется, достаточно агрегатов, нужных для полного восстановления дашборда.

### Key Entities

- **Analysis (Анализ)**: идентификатор, название ниши, главный ключ, маркетплейс, дата создания/обновления, версия методологии, Inputs, Aggregates, Results, AIVerdict, статус (черновик / с AI).
- **Inputs (Ручные переменные)**: цена, COGS, доставка/юнит, referral %, FBA-сбор, CPC, CVR, доля PPC, ACOS-цель, шт/день, сроки производства/доставки, бюджет, флаги дифференциации, ответы чеклиста, статусы критериев 3/7/8, «мой ASIN/бренд», список исключённых брендов (contamination), выбранные ключи кластера.
- **Aggregates (Агрегаты файлов)**: по Xray — строки ASIN (бренд, цена, продажи, выручка, отзывы, рейтинг, дата создания, продавец, fulfillment); по Cerebro — ключи (фраза, SV, тренд, bid, competing products, ABA share); по POE — nicheSummary, launchPotential, asinMetrics топ-N, searchTermMetrics, trendsMetrics, nichePdr топы; по SQP — purchase rate по ключам.
- **Results (Результаты)**: Критерий 1 (8 подпунктов: значение, порог, статус, источник/прокси), Gate 0–4, Критерий 2 (2a–2k), критерии 3–8, scorecard (5 осей + итог), стоп-вопросы, бюджет, распределение трафика, флаги сверки источников.
- **AIVerdict (Вердикт AI)**: вердикт, решающий гейт, обоснование по критериям, следующие шаги, гипотезы дифференциации, риски, комментарий по цене/комплектации, модель и дата, флаг «скорректирован правилами».
- **HistoryExport (Экспорт истории)**: версия схемы, дата экспорта, список Analysis.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Полный цикл «загрузил файлы → увидел дашборд с Критерием 1» занимает менее 2 минут работы пользователя и менее 5 секунд обработки для Xray ≤ 500 строк и Cerebro ≤ 10 000 строк.
- **SC-002**: На трёх реальных наборах (urinal screen deodorizer, oktoberfest plates, amaranthus + Xray/Cerebro 2026-08-21) значения 1a–1h совпадают с ручным расчётом по формулам скилла с отклонением ≤ 1 % (для округляемых) и одинаковым статусом.
- **SC-003**: Изменение любого ползунка отражается на графиках и статусах гейтов визуально мгновенно (≤ 100 мс) в 100 % случаев без сетевых запросов.
- **SC-004**: AI-ответ содержит все обязательные поля в 95 % запросов с первой попытки; в 100 % случаев вердикт не противоречит гейтам после валидации.
- **SC-005**: Анализ, загруженный из истории, восстанавливает 100 % входных переменных и статусов; скачанный HTML открывается офлайн и показывает те же значения KPI.
- **SC-006**: Приложение работает на бесплатном тарифе выбранного хостинга с нулевой платой за инфраструктуру; стоимость одного AI-анализа не превышает ориентир $0.10 при типичном объёме данных.
- **SC-007**: Неавторизованный посетитель не может вызвать AI-анализ (100 % отказов без пароля).

## Assumptions

- Пользователь — один или несколько доверенных операторов (личный инструмент), поэтому достаточно одного общего пароля доступа, без регистрации и ролей.
- История хранится на устройстве пользователя (браузер) с экспортом/импортом файлом; серверная синхронизация между устройствами — вне объёма v1 (дальнейший шаг при необходимости).
- Бесплатный хостинг подразумевает «засыпание» сервера при простое и холодный старт до ~1 минуты — допустимо; расчёты не зависят от сервера, сервер нужен только для AI.
- Railway на текущий момент не даёт постоянного бесплатного тарифа (только пробный кредит), поэтому целевой хостинг — Render Free (или Hugging Face Spaces / любой Docker-хост); конфигурация для Railway тоже прикладывается.
- Формат Xray/Cerebro — актуальные экспорты Helium 10 (заголовки как в `Helium_10_Xray_2026-08-21.csv` / `US_AMAZON_cerebro__2026-08-21.csv`); европейское форматирование чисел учитывается; другие локали — по возможности (автоопределение разделителя).
- POE JSON — формат `schemaVersion 1` расширения POE Analyzer / POE Collector.
- Пороги Критерия 1 и шкал берутся из скилла как значения по умолчанию и доступны для настройки пользователем в отдельной панели «Пороги» (методология эволюционирует — см. оговорку по 1h в скилле).
- Данные для критерия 4 («Customers say» с страницы Amazon) в v1 не собираются автоматически — берутся из POE `nichePdr` или вводятся вручную.
- Excel-выгрузка (`POE_Charts`, `Challenger_Criteria`) — не требуется пользователем для веб-версии; вместо неё HTML + JSON; XLSX — кандидат в бэклог.
- Оси Brand-fit и Operational Risk 5-осевой модели задаются пользователем (слайдеры/чеклист), так как не выводятся из файлов.
