# Feature Specification: Личные наборы порогов

**Feature Branch**: `011-threshold-presets` · **Created**: 2026-09-23 · **Status**: Implemented (см. tasks.md → «Выпуск»)

## Проблема

Пороги методологии («Пороги») правятся в каждом анализе отдельно и живут только в нём. Менеджер, который подобрал свои значения (например, для дешёвых товаров или своей категории), вынужден вводить их заново в каждом новом анализе или помнить, где они были. При этом чужие настройки видеть не нужно: у каждого своя практика, а значения по умолчанию должны оставаться общей отправной точкой.

## User Scenarios & Testing

### User Story 1 — Сохранить и загрузить набор (Priority: P1)

1. **Given** менеджер изменил несколько порогов в анализе, **When** нажимает «Сохранить текущие как…» и даёт имя, **Then** набор появляется в его списке «Мои наборы порогов» и содержит только отличия от значений по умолчанию.
2. **Given** есть сохранённый набор, **When** менеджер открывает другой анализ и нажимает «Загрузить в этот анализ», **Then** пороги анализа заменяются значениями набора, расчёт обновляется, изменённые пороги помечены «изменено».
3. **Given** выбран набор, **When** «Обновить набор» — набор перезаписывается текущими порогами; «Удалить» — удаляется после подтверждения.

### User Story 2 — Личное и общее по умолчанию (Priority: P1)

1. **Given** два пользователя, **When** один сохранил набор, **Then** другой его не видит и не может загрузить.
2. **Given** любой пользователь, **When** создаёт новый анализ («＋ Новый» или первый вход), **Then** пороги — по умолчанию (наборы применяются только явно кнопкой «Загрузить»).
3. Сами значения по умолчанию одинаковы для всех и меняются только в коде методологии.

## Requirements

- **FR-001**: Наборы хранятся в настройках учётной записи (не в браузере и не в анализе); не больше 20 наборов, имя до 60 знаков; в наборе — только известные пороги правильного типа и только отличия от умолчаний.
- **FR-002**: Загрузка набора меняет пороги только текущего анализа (сохраняются с ним как раньше); новый анализ стартует с умолчаний.
- **FR-003**: Пороги анализа по-прежнему сохраняются вместе с анализом и видны всем, кто его открывает (наборы — личные, пороги анализа — общие, как и весь анализ).
- **FR-004**: Во вкладке «Пороги» видно, сколько порогов в этом анализе отличается от умолчаний.

## Success Criteria

- **SC-001**: Сохранить набор и применить его к другому анализу — не больше 3 действий.
- **SC-002**: Чужие наборы недоступны через интерфейс и API (настройки учётной записи читает только их владелец).
- **SC-003**: Новый анализ никогда не наследует пороги предыдущего.
