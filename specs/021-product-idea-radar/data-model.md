# Data model: радар товарных идей

**Миграция 007** — `server/db/migrations/007_product_idea_radar.sql`.

Это первая сущность приложения, не выводимая из анализа, поэтому миграция здесь нужна (в отличие от спек 019 и 020, где её не было).

---

## Право доступа

```sql
ALTER TABLE users ADD COLUMN ideas_access boolean NOT NULL DEFAULT false;
```

Отдельная колонка, а не ключ в `users.settings`: настройки человек правит сам, и признак прав в таком поле — повышение прав на расстоянии одной будущей ошибки (D11). Администратору раздел открыт по роли, флаг для него не ставится.

## `idea_source` — заведённый раздел площадки

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid PK | |
| `platform` | text NOT NULL | какая площадка (закрытый набор из трёх) |
| `handle` | text NOT NULL | адрес раздела: категория, тема или имя канала |
| `title` | text NOT NULL | как человек его назвал |
| `active` | boolean NOT NULL DEFAULT true | приостановлен человеком |
| `paused_reason` | text | приостановлен системой после отказов подряд — причина |
| `threshold_mult` | numeric | своя кратность порога; NULL — берётся из общих порогов |
| `created_by` | uuid → users | автор |
| `created_at` | timestamptz NOT NULL DEFAULT now() | |

Ограничение `UNIQUE (platform, handle)` — один и тот же раздел не заводится дважды; при попытке система предупреждает о совпадении (FR-009), а не создаёт молча второй.

## `idea_run` — суточный обход одного раздела

| Поле | Тип | Смысл |
|---|---|---|
| `source_id` | uuid → idea_source ON DELETE CASCADE | |
| `run_date` | date NOT NULL | сутки обхода |
| `status` | text NOT NULL | `ok` \| `failed` \| `skipped` |
| `fail_code` | text | отклонено площадкой, исчерпан лимит, канал недоступен, ответ не разобран, язык не тот |
| `fail_message` | text | человеческими словами |
| `seen_count` | integer | сколько элементов обработано |
| `passed_count` | integer | сколько прошло отбор |
| `background` | jsonb | медиана фона и размер выборки, по которым считался отбор |
| `spent` | numeric | израсходовано на этот обход |
| `via` | text | прямой запрос или обход защиты (D7) |
| `started_at`, `finished_at` | timestamptz | |

**Первичный ключ `(source_id, run_date)`** — это и есть защита от повторного обхода в те же сутки (FR-004, SC-006) и от двойного расхода после перезапуска (FR-005, SC-007). Правило держит база, а не договорённость в коде.

```sql
CONSTRAINT ck_run_fail_has_reason CHECK ((status = 'failed') = (fail_code IS NOT NULL))
```

Связь «неудача ⟺ названа причина» держит база. Строка `failed` без причины невозможна — а именно такая строка и выглядела бы в ленте пустотой (ворота SC-002).

## `idea_item` — элемент, не прошедший отбор

Хранится несколько суток (порог, умолчание — неделя) и удаляется. Нужен ровно затем, чтобы человек подвинул порог и сразу увидел результат на настоящих данных (FR-014); для ленты и для фона не нужен.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid PK | |
| `source_id` | uuid → idea_source ON DELETE CASCADE | |
| `run_date` | date NOT NULL | |
| `external_id` | text NOT NULL | опознаватель на площадке |
| `title` | text | |
| `url` | text | |
| `published_at` | timestamptz | когда появилось на площадке; NULL — площадка не сказала |
| `metric` | numeric | приведённый к возрасту показатель; NULL — показателя нет |
| `raw` | jsonb | исходные числа элемента |

Уборка: `DELETE FROM idea_item WHERE run_date < current_date - :keep_days`.

## `idea_candidate` — прошедший отбор

Живёт долго: это и есть лента и память решений.

| Поле | Тип | Смысл |
|---|---|---|
| `id` | uuid PK | |
| `source_id` | uuid → idea_source ON DELETE SET NULL | раздел удалён — кандидат остаётся |
| `external_id` | text NOT NULL | |
| `title` | text NOT NULL | |
| `url` | text NOT NULL | ссылка на первоисточник (FR-016) |
| `published_at` | timestamptz | |
| `first_seen_on` | date NOT NULL | когда выделился впервые |
| `last_seen_on` | date NOT NULL | когда выделялся в последний раз |
| `days_held` | integer NOT NULL DEFAULT 1 | сколько суток держится (FR-021) |
| `metric` | numeric NOT NULL | число, из-за которого отобран |
| `background` | numeric NOT NULL | фон, с которым сравнивался |
| `ratio` | numeric NOT NULL | во сколько раз выше (показывается человеку) |
| `platforms` | text[] NOT NULL | на каких площадках найден (D10) |
| `decision` | text NOT NULL DEFAULT 'none' | `none` \| `kept` \| `dismissed` |
| `decided_by`, `decided_at` | uuid → users, timestamptz | |
| `analysis_id` | uuid → analyses ON DELETE SET NULL | анализ, созданный из идеи |
| `snippet` | text | короткий исходный текст — для пояснения словами |

`UNIQUE (source_id, external_id)` — один элемент одна запись; повторное появление поднимает `last_seen_on` и `days_held`, а не создаёт вторую строку (FR-021).

`decision = 'dismissed'` убирает из ленты навсегда, но запись остаётся и её можно вернуть (FR-022). **Отклонённое не удаляется** — иначе следующий же обход вернул бы его в ленту как новое.

`ON DELETE SET NULL` на анализе — удаление анализа не трогает идею (симметрично FR-003 прежней редакции: связь односторонняя).

## `idea_spend` — расход по суткам

| Поле | Тип | Смысл |
|---|---|---|
| `spend_date` | date PK | |
| `spent` | numeric NOT NULL DEFAULT 0 | израсходовано за сутки всеми разделами |

Отдельная строка на сутки, а не сумма по `idea_run`: потолок должен проверяться **до** запуска очередного обхода и дешёвым запросом, а не сложением всех обходов дня (FR-031, SC-008).

## Состояние источника

```
активен ──(человек приостановил)──> приостановлен человеком ──(человек запустил)──> активен
   │
   └──(N отказов подряд)──> приостановлен системой ──(человек запустил)──> активен
```

Приостановка системой ставит `paused_reason` и прекращает расход (FR-027). Разница между двумя приостановками видна человеку: одну сделал он, другую — система, и у второй есть причина.

## Что миграция НЕ делает

- Не трогает `analyses`, `analysis_versions`, `analysis_outcome` и ничего в расчёте ниши. Ворота SC-009 проверяют это контрольным отпечатком.
- Не переносит ничего из прошлого: до этой спеки радара не существовало, переносить нечего.
