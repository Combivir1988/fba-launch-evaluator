# Contract: что запрашивается у площадок и что разбирается

Всё измерено живыми запросами **2026-11-12**. Разбор — чистые функции в `shared/idea-parse.js`, проверяемые на сохранённых образцах; в сеть тесты не ходят.

**Три замера опровергли то, что в первой редакции этого файла было записано предположением.** Опровержения отмечены словом **ОПРОВЕРГНУТО** и перенесены в research.md.

---

## Общие правила для всех трёх

1. **Один запрос на раздел в сутки.** Фон считается из той же выборки (D2), второго запроса не нужно.
2. **Прямой запрос первым, обход защиты запасным** (D7). Каким путём пришёл ответ — записывается в обход и видно человеку.
3. **Язык и регион задаются явно** (D8) — параметрами адреса и заголовком. Иначе площадка выбирает язык по адресу, с которого пришёл запрос.
4. **Ответ не на том языке — это отказ с причиной «язык не тот», а не пустота.** Разборщик обязан это различать: пустой разбор локализованного ответа выглядел бы как «ничего не нашлось».
5. **Элемент без опознавателя или без ссылки отбрасывается** и считается в «не разобрано».
6. **Выборка, в которой почти нет свежего, — это отказ с причиной «отбор не применился»**, а не пустая лента. См. раздел про видео: там это измеренный случай, а не гипотетический.

## Мессенджер — превью публичного канала

**Запрос**: страница предпросмотра канала по его имени. Листание назад — параметром, но для суточного обхода не нужно: хватает одной страницы.

**Замер**: ответ **200**, **127 КБ**, **20 постов**, прямым запросом, без обхода защиты.

**Разбирается из каждого поста**:

| Величина | Вид в ответе | Примечание |
|---|---|---|
| опознаватель | `data-post` — имя канала и номер сообщения | |
| ссылка | адрес поста | |
| текст | содержимое поста | хранится только у кандидатов |
| дата | **абсолютная**, ISO с зоной — `2026-05-14T16:08:31+00:00` | от языка не зависит, разбирать безопасно |
| просмотры | **сокращённо** — `1.68M`, `3.13M`, `812K` | нужен разбор суффиксов |

**Чем это лучше остальных**: дата абсолютная. Ловушки с языком (D8) здесь нет.

**Ограничение, которое обязано быть сказано человеку** (FR-010, SC-012): поиска по площадке не существует. Радар видит только названные каналы — и ничего больше.

**Чего не бывает**: у личных имён предпросмотра нет, только у каналов. Закрытый канал недоступен. И то и другое — отказ с названной причиной.

**Образец**: `tests/fixtures/idea-telegram.html` — 20 постов, адреса картинок и видео вырезаны (к разбору отношения не имеют).

## Видео — страница поиска по теме

**Запрос**: страница результатов поиска по теме раздела, **с явно закреплённым языком и регионом** и **с фильтром по дате загрузки**.

**Замер**: ответ **200**, 1,2–1,7 МБ, данные страницы встроены в неё целиком, **20 роликов**, прямым запросом, без обхода защиты.

### ОПРОВЕРГНУТО: выдача по умолчанию для радара непригодна

В первой редакции было записано: «выдача упорядочена по совпадению с темой, а не по свежести; если свежего окажется мало, запрос дополняется упорядочиванием по дате». Измерено:

- **выдача по умолчанию**: возраст всех 17 роликов — `9y, 4y, 5y, 4y, 10y, 8y, 11y, 5y, 3y, 1y, 1y, 10y, 3y, 5y, 1y, 2y, 6y`. Внутри окна сопоставимости (90 суток) — **ноль из семнадцати**;
- **упорядочивание по дате загрузки не работает**: тот же набор старых роликов, порядок почти не изменился;
- **фильтр по дате работает**: «за этот месяц» — 20 роликов возрастом от 20 часов до 4 недель; «за эту неделю» — 20 роликов от 3 часов до 7 суток.

**Следствие, и оно жёсткое**: без фильтра по дате внутри окна сопоставимости не оказалось бы **ни одного** элемента, `minSample` не набрался бы **никогда**, и раздел каждый день честно говорил бы «фона не из чего посчитать». Источник был бы мёртв навсегда — и выглядел бы при этом исправным.

**Решение**: фильтр по дате — **часть запроса, а не настройка**. Умолчание — **«за этот месяц»**: вся выборка попадает внутрь `compareWindowDays = 90`, и элементов в ней больше, чем при недельном фильтре.

**Сторож** (общее правило 6): если в разобранной выборке доля элементов внутри окна сопоставимости мала, значит фильтр не применился — это **отказ с причиной «отбор не применился»**, а не пустая лента. Молчаливое вырождение здесь выглядело бы как исправная работа.

**Разбирается из каждого ролика**:

| Величина | Вид в ответе | Примечание |
|---|---|---|
| опознаватель | `videoId` | |
| название, канал | текст | |
| просмотры | **текстом** — `31,238 views`, `1 view`, **`No views`** | точного числа в выдаче **нет**, только формат |
| возраст | **текстом, относительно** — `20h ago`, `1d ago`, `11d ago`, `2w ago`, `4w ago` | сокращённая форма |
| краткое описание | `detailedMetadataSnippets` — **в том же ответе** | измерено: есть у 16 из 20; нет — поле пустое, на отбор не влияет |

**`No views` — это не ноль.** Измеренный случай: два ролика из двадцати. По правилу отсутствия `value = null`, элемент не кандидат и не ноль, растёт счётчик `noMetric`. Подстановка нуля означала бы «вещь никому не интересна», что противоположно «мы не знаем».

### Замеренная ловушка языка (D8)

Тот же запрос без закрепления языка вернул:

| По-английски | На чужом языке |
|---|---|
| `31,238 views` | `31 238 wyświetleń` |
| `1 view` | `1 wyświetlenie` |
| `2 views` | `2 wyświetlenia` |
| `No views` | `Brak wyświetleń` |
| `20h ago` | `20 godz. temu` |
| `1d ago` | `1 dzień temu` |
| `11d ago` | `11 dni temu` |
| `4w ago` | `4 tyg. temu` |

Разборщик под английский не нашёл бы здесь **ничего** и записал бы «нет данных»: честно по форме, неверно по сути.

**Две ловушки в одной, и вторая тише первой**: разделитель разрядов — **неразрывный пробел** (`31 238`), а не запятая. Разборщик, который чистит только запятые, получил бы на таком числе `31` вместо `31238` — то есть **не пустоту, а неверное число**, которое никакой сторож пустоты не поймает.

### Чего здесь НЕТ: содержания ролика

Из выдачи берутся **название, канал, краткое описание и числа**. Звук не расшифровывается, страница ролика не открывается.

**Почему не нужно для отбора**: отбор считается по числам (просмотры, приведённые к возрасту). Содержание не участвует в нём ни на одном шаге, и расшифровка не изменила бы ни одного кандидата.

**Почему это отдельное решение, а не умолчание**: расшифровка — это запрос на каждый ролик сверх обхода, и у части роликов её вообще нет. Делать её имеет смысл **только для прошедших отбор** (их единицы в сутки, а не двадцать), и только если окажется, что названия и описания не хватает, чтобы понять, о чём речь. Это **измеряется на первых живых сутках** чтением настоящих кандидатов, а не предполагается сейчас.

**Чем она опасна** (FR-017, ворота SC-005): пересказ содержания, сделанный моделью, — самое вероятное место, где раздел начнёт говорить «тут хорошая товарная идея». Весь раздел построен на том, что он этого не утверждает. Если расшифровка когда-нибудь появится, она обязана давать **пересказ сказанного**, а не вывод о пригодности к продаже, и проверяться тем же чтением всех текстов раздела.

**Образцы**: `tests/fixtures/idea-video-en.json` (20 роликов, английский) и `tests/fixtures/idea-video-other-locale.json` (20 роликов, чужой язык). Оба обрезаны до списка роликов: полный ответ весит 1,2 МБ, образец — 38 КБ.

## Краудфандинг — лента категории

**Запрос**: лента проектов категории в машиночитаемом виде — тот же адрес, который площадка вызывает сама; ни ключа, ни учётной записи не требуется. **Отбор — по популярности среди идущих сейчас проектов.**

**Замер прямого запроса**: отклонён — **403**, страница проверки браузера. Защита проверяет не учётные данные, а признаки клиента. Эта площадка **обязательно** идёт через обход защиты.

### ОПРОВЕРГНУТО: она не самая дорогая

В первой редакции было записано: «она же самая дорогая». Измерено: запрос через обход защиты обошёлся в **1 кредит** — столько же, сколько простой запрос. Обход защиты поднялся до датацентрового прокси и дальше не пошёл.

**Оговорка, которую нельзя опускать**: обход защиты повышает уровень сам, когда это нужно, и тогда цена вырастет. Поэтому **фактическая стоимость каждого ответа берётся из самого ответа** (`context.cost.total`) и пишется в обход, а не предполагается по таблице.

### ОПРОВЕРГНУТО: «самые новые» для радара непригодны

Отбор по новизне возвращает проекты, запущенные сегодня: из 12 у **шести** собрано ровно `0`, у остальных — от 657 до 84 759 в разных валютах. Это не «ими никто не интересуется», это «ещё слишком рано». Фон такой выборки вырождается, и отбор либо не даёт никого, либо даёт случайных.

**Решение**: отбор **по популярности среди идущих сейчас** (`state=live`). Замер такой выборки: 12 проектов возрастом 0–7 суток, собрано от 13 837 до 2 082 121 в приведении к одной валюте. Фон считается, кандидаты выделяются.

### Валюта — ловушка, которая молча врёт

В одном ответе измерены **четыре разные валюты** (USD, GBP, HKD, EUR), и поле `pledged` — **в своей валюте у каждого проекта**. Сравнивать их между собой нельзя: проект на `3 294 657 HKD` и проект на `84 759 GBP` в сыром виде различаются в 39 раз, а в приведении — в 3,7 раза.

| Поле | Тип | Годится |
|---|---|---|
| `pledged` | число, **в своей валюте** | **НЕТ** — сравнение между валютами бессмысленно |
| `usd_pledged` | **строка** | формально годится, но проверка «это число?» его **молча отбросит** |
| `converted_pledged_amount` | **число**, в `current_currency` | **ДА** — это и берётся |

**Почему это записано так подробно**: `usd_pledged` приходит строкой. Разборщик, который проверяет `typeof === "number"`, отбросит её без единого признака ошибки и запишет «показателя нет» у **всех** проектов сразу. Ошибка тихая и выглядит как исправная работа.

**Разбирается из каждого проекта** (имена полей **подтверждены живым ответом**):

| Величина | Поле | Примечание |
|---|---|---|
| опознаватель | `id` | |
| название | `name` | |
| ссылка | `urls.web.project` | |
| краткое описание | `blurb` | |
| собрано | **`converted_pledged_amount`** | число, в одной валюте; `pledged` **не использовать** |
| цель | `goal` | **в своей валюте** — поэтому доля от цели считается `pledged / goal`, обе величины одной валюты |
| доля от цели | `percent_funded` | площадка считает сама; расчёт сверяется с ней |
| поддержавших | `backers_count` | показывается человеку, в отбор не входит |
| дата запуска | `launched_at` | **unix-секунды**, не ISO |
| валюта | `currency`, `current_currency` | смешение валют в разделе — норма, а не исключение |
| состояние | `state` | |

**Размер выборки**: **12** проектов в ответе (не 20), `total_hits` называет общее число, `has_more` говорит, что есть продолжение. При `minSample = 5` одной страницы хватает; листание не нужно.

**Образец**: `tests/fixtures/idea-crowdfunding.json` — 12 проектов, картинки и данные авторов вырезаны. 13 КБ.

## Рынок раздела: США и Европа

**Замерено 2026-11-12. Площадки ведут себя по-разному, и это решает, где рынок вообще имеет смысл.**

### Краудфандинг — область РАБОТАЕТ

| Запрос | Всего проектов | Страны в ответе | Пересечение с общей лентой |
|---|---|---|---|
| без области | 398 | US, GB, HK вперемешку | — |
| США | 183 | US ×12 | 5 из 12 |
| Европа | 100 | GB, BE, ES, FR, PL | 2 из 12 |

Это **разные пулы**, а не оттенки одного. Без области европейские проекты в ленту почти не попадают: в измеренном ответе их было два из двенадцати.

### Видео — область почти ничего не меняет

При **английском** запросе выдача по US, GB, DE, FR и PL совпадает на **18–19 роликов из 20**. Вторая область дала бы один-два новых ролика за второй запрос.

**Настоящий рычаг — язык запроса:**

| Запрос | Роликов | Своих, которых нет в выдаче США |
|---|---|---|
| `bike chain cleaner` (US) | 20 | — |
| `Fahrradkette reinigen` (DE) | 20 | **17** |
| `czyszczenie łańcucha rowerowego` (PL) | 23 | **20** |

**Следствие для интерфейса**: европейский раздел видео заводится **отдельной строкой с фразой на местном языке**. Обещать, что «область = Европа», было бы неправдой — и неправдой проверяемой.

**Важно и проверено**: при запросе на любом языке и при любой области текст чисел остаётся английским, если закреплён `hl`. Проверено на 143 роликах. **Ловушку D8 закрывает `hl`, а не область.**

### Канал мессенджера — области нет вовсе

Поиска по площадке не существует, разделения по странам тоже. Рынок у такого раздела только подписывает его в списке и на запрос не влияет.

### Почему рынок — часть опознавателя раздела

США и Европа — **два раздела со своим фоном у каждого**, а не один раздел с двумя запросами. Сложить их выборки в один фон было бы ровно той ошибкой, против которой написаны ворота SC-003: аудитории разного размера, и общая медиана выключила бы меньшую.

Поэтому `UNIQUE (platform, handle, market)`: один и тот же запрос по США и по Европе — это не дубль, а два раздела; тот же запрос на том же рынке дважды — дубль, и его не пускает база.

## Оценка расхода до запуска (FR-029)

**Проверено, а не предположено**: запрос с признаком оценки стоимости **выполняется как обычный** и возвращает содержимое страницы вместе с ценой. Предварительной оценки **без выполнения** эта служба не даёт.

**Следствие для FR-029**: число «сколько будет стоить сутки» считается по таблице множителей и **помечается как оценка**, а рядом показывается **фактический расход** из `context.cost.total` каждого ответа. Называть оценку фактом запрещено — в этом вся разница между «мы прикинули» и «мы знаем».
