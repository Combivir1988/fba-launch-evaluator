# Quickstart: как убедиться, что раздел «Статистика» сделан правильно

Пять проверок. Первые три — бинарные ворота: не прошло — не сделано, сколько бы графиков ни рисовалось.

---

## Ворота 1 — цифры не читаются из сохранённого (SC-003)

**Это главная проверка спеки.** Реализация, которая берёт `core.results` вместо пересчёта, выглядит правильной, быстрее и проходит всё остальное.

Тест пишется **до** реализации.

```
tests/stats-outcome.test.js
  → анализ-подложка: в core.results лежит вердикт «no_go» с decisiveGate «Amazon в нише»,
    а данные таковы, что текущая методика даёт «rework» по Gate 1
  → assert: outcome.verdict.ceiling === "rework"
  → assert: outcome.verdict.decisiveGate === "Gate 1"
  → assert: outcome.stored.ceiling === "no_go"   // расхождение видно, но на цифры не влияет
```

Реализация, читающая сохранённый результат, падает здесь и больше нигде.

**На живых данных** то же ворото читается как: доля «Amazon в нише» среди решающих причин — **17 %**, а не 68 %.

## Ворота 2 — анализы не изменены (SC-007, FR-009)

Открытие раздела — операция только для чтения в отношении `analyses`.

```sql
-- до
SELECT md5(string_agg(id::text || version::text || updated_at::text, '|' ORDER BY id)) FROM analyses;
SELECT count(*) FROM analysis_versions;
```

Открыть раздел десять раз, в том числе с полным пересчётом.

```sql
-- после: оба значения обязаны совпасть до символа
```

Плюс тест: `tests/stats-api.test.js` → «десять открытий раздела не меняют ни version, ни updated_at, ни число версий».

## Ворота 3 — без права не достаётся ни одна цифра (SC-001, FR-002)

```
анна — без права:
  GET /api/stats                → 403 no_stats_access
  тело ответа                   → ни одного числа: ни n, ни total, ни названия ниши
  GET /api/auth/me              → statsAccess: false
босс (админ) выдаёт право:
  PATCH /api/users/<анна>       { statsAccess: true }   → 200
  анна: GET /api/stats          → 200
босс снимает:
  PATCH /api/users/<анна>       { statsAccess: false }
  анна: GET /api/stats          → 403 уже на следующем запросе, без ожидания сеанса
админ без выданного флага:
  GET /api/stats                → 200 (право по роли)
```

Отдельно глазами: у человека без права **нет кнопки** раздела в шапке.

## Проверка 4 — цифры сходятся с эталоном (SC-002)

Эталон — локальный пайплайн `.data/stats/` на тех же данных:

```
node .data/stats/1-recompute.mjs
node .data/stats/2-mkdata.mjs
```

Сверить с разделом:

| Показатель | Эталон 2026-11-02 |
|---|---|
| No-Go / Доработка | 66 % / 31 %, Go — 1 ниша |
| Решающая причина | экономика 43 %, конкуренция 35 %, не доведён до конца 12 % |
| Проблема есть вообще | конкуренция 97 %, экономика 72 % |
| Критерий 1 | прошли 2 из 65, среднее 3,2 из 8 |
| Расхождение сохранённого и пересчитанного | 17 анализов |
| Пустых черновиков вне статистики | 2 (из 67 живых) |

Расходится — виновато ядро, а не оформление: сверять `shared/stats-summary.js` с `2-mkdata.mjs`, а не подгонять числа.

**Выполнено 2026-11-02, сошлось до цифры** (`.data/live-check.mjs` — только чтение, в базу не пишет): 67 живых / 65 считаются / 2 пустых; No-Go 66 % · Доработка 31 % · Go 1; экономика 43 % · конкуренция 35 % · не доведён до конца 12 %; «есть вообще» конкуренция 97 % · экономика 72 %; Критерий 1 прошли 2 из 65, среднее 3,2; расхождение сохранённого с пересчитанным — 17; **«Amazon в нише» как решающая причина — 11 из 65 = 17 %, а не 68 %**.

Заодно замерено на том же прогоне: полный пересчёт 19,5 с (291 мс на анализ), **RSS 162 МБ** вместо 329 — потоковый пересчёт по одному держится (D5); итог одного анализа 1519 Б в среднем, 1867 Б максимум (тест держит потолок 4 КБ); 200 итогов — 0,29 МБ, свёртка 0,8 мс на запрос, то есть SC-006 на свежих цифрах — десятки миллисекунд с запасом.

## Проверка 5 — методика поехала, цифры поехали (SC-005, FR-026)

```
1. Открыть раздел, запомнить цифры и computedAt.
2. Изменить любой файл shared/ (достаточно комментария), перезапустить сервер.
3. Открыть раздел снова.
   → freshness.methodChanged: true, recomputing: true, цифры ПРЕЖНИЕ с пометкой
4. Дождаться окончания догона, открыть ещё раз.
   → computedAt новый; если менялся сам расчёт — цифры другие.
```

Если шаг 3 показывает прежние цифры **без** пометки и `stale: 0` — признак версии методики не работает, и раздел повторяет ровно тот баг, против которого написан.

## Скорость (SC-006)

Открытие раздела — не дольше **3 с** при 200 анализах, в обоих состояниях:

| Состояние | Ожидание |
|---|---|
| всё свежо | десятки миллисекунд: два дешёвых запроса и свёртка 0,33 МБ |
| идёт догон | столько же: ответ отдаётся из кэша, расчёт не в запросе |
| устарело 1…5 | до ~1,4 с (≈283 мс на анализ, замер) |

Память: пересчёт берёт анализы **по одному**. Если в логе виден рост RSS к 300 МБ — где-то загрузились все сразу (D5 нарушен).
