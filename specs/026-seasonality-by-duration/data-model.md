# Data Model: сезонность по длительности (spec 026)

Хранения нет, миграции нет. Описаны только формы в памяти: что отдаёт новый модуль и что появляется в подпункте 1g.

---

## 1. Вход: недельный ряд спроса

Берётся из уже существующего `poe.trends` — массив точек вида `{ date: "YYYY-MM-DD", sv: число | null }`.

Правила отбора те же, что и сегодня:

- точки с `sv === null` **исключаются** (пропуск — не нулевой спрос и не просадка);
- берутся последние **52** точки;
- если осталось меньше `minTrendWeeks` (8) — расчёт не делается.

---

## 2. Выход модуля `shared/seasonality.js`

Чистая функция `seasonality(trends, { lowOf, minRun })` → объект или `null`.

```js
{
  weeks: 52,            // длина фактической истории после отбора
  normal: 18400,        // «обычный уровень» — медиана ряда (D1)
  lowOf: 0.7,           // доля медианы, ниже которой неделя считается слабой (D2)
  downShare: 0.23,      // ДОЛЯ ИСТОРИИ В ПРОСАДКАХ — величина, по которой выносится статус (D4)
  downWeeks: 12,        // то же в неделях, для человеческой фразы
  dips: 2,              // число просадок (D4)
  longest: 8,           // длина самой длинной просадки в неделях (D4)
  depth: 0.31,          // средняя глубина недель в просадках, доля от обычного уровня (D6)
  months: ["06", "09"], // первый и последний месяц САМОЙ ДЛИННОЙ просадки (D7)
  monthsLabel: "с июня по сентябрь"
}
```

### Правила

| Поле | Правило |
| --- | --- |
| `weeks` | число точек с известным `sv` после `slice(-52)`; **все доли считаются от него**, не от 52 (FR-011) |
| `normal` | медиана ряда; при `normal === 0` расчёт невозможен — функция возвращает `null` с причиной |
| `downShare` | `downWeeks / weeks`; `0`, если просадок нет |
| `downWeeks` | сумма длин просадок — отрезков **не короче `minRun`** подряд, где `sv < normal × lowOf` (D3) |
| `dips` | число таких отрезков; `0`, если их нет |
| `longest` | длина наибольшего отрезка; `0`, если просадок нет |
| `depth` | среднее `(normal − sv) / normal` по неделям **внутри просадок**; `0`, если просадок нет (D6) |
| `months` | `["MM", "MM"]` — месяцы первой и последней недели самой длинной просадки; `[]`, если просадок нет |
| `monthsLabel` | `""` при отсутствии просадок; `"август"` при совпадении месяцев; `"с июня по сентябрь"` при диапазоне |

### Когда функция возвращает `null`

- точек с известным `sv` меньше `minTrendWeeks`;
- медиана ряда равна нулю (весь ряд нулевой — судить не по чему).

В обоих случаях возвращается `{ reason }`, чтобы подпункт мог назвать причину словами, а не промолчать.

## 3. Подпункт 1g в результатах расчёта

Форма записи подпункта не меняется — меняется её содержимое.

```js
items["1g"] = {
  value: 0.23,              // БЫЛО: (пик − минимум) / пик. СТАЛО: доля истории в просадках
  status: "fail",           // ok | warn | fail | na
  source: "poe",
  unit: "%",
  threshold: "ниже обычного спроса < 8 % года OK · > 20 % НЕ OK",
  note: "12 недель из 52 (23 % года) ниже обычного спроса; в среднем на 31 % ниже; самая длинная просадка 8 недель с июня по сентябрь; просадок 2",
  extra: {                  // ДОБАВОЧНЫЕ поля — исключаются из контрольного отпечатка (D11)
    downShare: 0.23,
    depth: 0.31,
    months: ["06", "09"],
    dips: 2,
    longest: 8,
    lowOf: 0.7
  }
}
```

### Что изменилось и что нет

| | Было | Стало |
| --- | --- | --- |
| `value` | отношение крайностей, медиана 64 % | доля истории в просадках, медиана 2 % |
| `status` | `ok 1 · warn 14 · fail 51` | `ok 47 · warn 7 · fail 12` |
| `unit` | `%` | `%` (не меняется) |
| `source` | `poe` | `poe` (не меняется) |
| `extra` | отсутствовало | пять объясняющих величин |
| ручной ответ человека | главнее вычисленного | **главнее вычисленного** (FR-014, не меняется) |

## 4. Пороги

Группа `criterion1` в `shared/thresholds.js`:

| Было | Стало | Значение | Смысл |
| --- | --- | --- | --- |
| `seasonOk: 0.30` | **убран** | — | старый ключ с новым смыслом был бы тихой ошибкой (D9) |
| `seasonFail: 0.50` | **убран** | — | то же |
| — | `seasonDownOk` | `0.08` | доля истории в просадках, ниже которой «ок» |
| — | `seasonDownFail` | `0.20` | доля, выше которой «не ок» |
| — | `seasonLowOf` | `0.70` | доля обычного уровня, ниже которой неделя слабая |
| — | `seasonMinRun` | `2` | минимальная длина просадки в неделях |
| `minTrendWeeks: 8` | без изменений | `8` | меньше — «не хватает истории» |

Все четыре новых ключа — часть методики и живут в общих порогах, то есть редактируются во вкладке «Пороги» так же, как остальные. Личные наборы со старыми ключами деградируют мягко: `thresholdOverrides` пропускает только ключи, которые есть в умолчаниях.

## 5. Что зависит от подпункта и меняется само

| Потребитель | Что берёт | Следствие |
| --- | --- | --- |
| `shared/scorecard.js` | `status` подпункта 1g в рыночной оси | оценка оси растёт там, где статус улучшился |
| `shared/verdict-rules.js` | Scorecard | вердикт может сдвинуться — измеряется, а не предполагается |
| `shared/criterion1.js` | `status` → `okCount`, `pass` | Критерий 1 проходят чаще |
| `shared/borderline.js` | `value` и пороги | переводится вручную (D10) |
| `shared/compute.js:56` | весь объект подпункта | **правки не требует**: новые поля едут вместе с объектом (D13) |

Явно **не** зависят и не должны сдвинуться: экономика, конкуренция, трафик, вход в нишу, цена конфигурации, распределение цен, товарная линейка, план измерений, патенты, этап 3. Это проверяют ворота SC-004.
