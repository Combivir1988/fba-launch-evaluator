# Contract: `shared/seasonality.js`

Чистая функция без побочных действий. Вход — недельный ряд, выход — числа. Статусов не выносит: решение о статусе принимает `criterion1.js`, и это намеренное разделение (числа отдельно, пороги отдельно).

---

## Сигнатура

```js
seasonality(trends, { lowOf = 0.7, minRun = 2, minWeeks = 8 } = {})
```

| Аргумент | Что это |
| --- | --- |
| `trends` | массив `{ date: "YYYY-MM-DD", sv: число \| null }` |
| `lowOf` | доля обычного уровня, ниже которой неделя считается слабой |
| `minRun` | минимальная длина просадки в неделях |
| `minWeeks` | минимальная длина истории, при которой расчёт вообще делается |

Возвращает объект результата (раздел 3) **или** `{ reason: "..." }`.

---

## 1. Отбор ряда

```
points = trends.filter(p => p.sv !== null).slice(-52)
weeks  = points.length
```

- `sv === null` — **пропуск**, он не слабая неделя и не нормальная; из ряда исключается и в `weeks` не входит.
- Берутся последние 52 точки; если их меньше — берутся все, какие есть.
- Порядок точек сохраняется: просадки ищутся по соседству во времени.

**Правило отсутствия:** `weeks < minWeeks` → `{ reason: "short_history" }`.

---

## 2. Обычный уровень и слабые недели

```
normal = медиана(sv по points)
```

**Правило отсутствия:** `normal <= 0` → `{ reason: "no_demand" }` — весь ряд нулевой, судить не по чему, деления на ноль не происходит.

```
low[i] = sv[i] < normal × lowOf
```

Сравнение **строгое**: неделя ровно на границе `normal × lowOf` слабой не считается. Граница принадлежит норме — так же, как в spec 024 верхний коридор включает свою границу.

---

## 3. Просадки

Просадка — максимальный непрерывный отрезок подряд идущих `low[i] === true` длиной **не менее `minRun`**.

```
runs    = все максимальные отрезки low
dipsArr = runs.filter(длина >= minRun)
```

Отрезки короче `minRun` **отбрасываются целиком** и не входят ни в одну величину: ни в долю, ни в глубину, ни в число просадок. Одиночная слабая неделя — не просадка.

### Выход

```
downWeeks = сумма длин dipsArr
downShare = downWeeks / weeks
dips      = dipsArr.length
longest   = максимальная длина в dipsArr   (0, если dipsArr пуст)
depth     = среднее (normal − sv[i]) / normal по всем i внутри dipsArr   (0, если пуст)
months    = ["MM" первой недели самого длинного отрезка, "MM" последней]   ([], если пуст)
```

**`downShare` считается от `weeks`, а не от 52** — это требование FR-011 и ворота SC-003.

## 4. Словесный период

| Условие | `monthsLabel` |
| --- | --- |
| просадок нет | `""` |
| оба месяца совпали | `"август"` |
| месяцы разные | `"с июня по сентябрь"` |

Названия месяцев — родительный падеж для диапазона, именительный для одиночного.

## 5. Статус в `criterion1.js`

```
value = downShare

status = ok    при value < seasonDownOk
         fail  при value > seasonDownFail
         warn  иначе
```

Границы включаются в «погранично»: ровно `0.08` — это `warn`, ровно `0.20` — тоже `warn`. Так же устроены остальные подпункты Критерия 1.

**Правила отсутствия:**

| Что вернул модуль | Статус | Что пишется |
| --- | --- | --- |
| `{ reason: "short_history" }` | `na` | «не хватает истории трендов (меньше 8 недель) — это не «НЕ OK»» |
| `{ reason: "no_demand" }` | `na` | «в ряду нет ненулевого спроса — сезонность считать не по чему» |
| `poe` отсутствует целиком | `na` | как сегодня |
| ручной ответ человека | его ответ | ручной ответ главнее вычисленного (FR-014) |

## 7. Контрольные значения

Тесты обязаны воспроизводить эти примеры.

### A. Ровный ряд с одним всплеском (ворота SC-001)

Вход: 52 недели по 1000, одна неделя 3000.

```
normal = 1000 · low = ни одной · dips = 0 · downShare = 0 · depth = 0 · months = []
статус: ok
```

Добавление ещё одной недели 3000 не меняет ни одного поля, кроме `weeks`.

### B. Ровный ряд с одной мёртвой неделей (ворота SC-001)

Вход: 52 недели по 1000, одна неделя 200.

```
normal = 1000 · low = одна неделя · runs = [1] · dipsArr = [] (1 < minRun)
dips = 0 · downShare = 0 · depth = 0
статус: ok
```

**Ключевой случай.** Без правила `minRun` было бы `downShare = 1/52 = 1,9 %` — всё ещё `ok` на длинной истории, **но на истории в 11 недель это 9,1 %**, то есть `warn`, и ворота упали бы. Правило делает инвариант верным при любой длине.

### C. Летний товар (ворота SC-002)

Вход: 26 недель по 1000, затем 26 недель по 300.

```
normal = 650 (медиана ряда из двух уровней)
low = недели со 300 (300 < 650 × 0,7 = 455) → 26 недель
dipsArr = [26] · downShare = 26/52 = 0,50 · dips = 1 · longest = 26
depth = (650 − 300) / 650 = 0,538
статус: fail (0,50 > 0,20)
```

### D. Короткая история (ворота SC-003)

Вход: 12 недель, из них 2 подряд ниже порога.

```
weeks = 12 · dipsArr = [2] · downShare = 2/12 = 0,167
статус: warn (0,08 ≤ 0,167 ≤ 0,20)
```

Если бы доля считалась от 52, вышло бы `0,038` и `ok` — тест на это и падает.

Вход: 6 недель → `{ reason: "short_history" }`, статус `na`.

### E. Две просадки

Вход: 52 недели, просадки длиной 8 и 4 недели, между ними норма.

```
downWeeks = 12 · downShare = 0,231 · dips = 2 · longest = 8
статус: fail
месяцы берутся от отрезка длиной 8, а не от обоих
```

## 8. Чего функция не делает

- не выносит статус — только числа;
- не читает пороги из глобального состояния — всё приходит аргументами;
- не прогнозирует будущие недели;
- не отличает «сезон кончился» от «ниша умирает» — направление спроса меряет другой подпункт;
- не агрегирует по месяцам и кварталам — ряд остаётся недельным (замерено: агрегация задачу не решает).
