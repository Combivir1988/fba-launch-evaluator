# Contract: запуск длительной операции

Шесть маршрутов, одно правило. Ниже — что приходит, что уходит и что обязано произойти.

---

## 1. Маршруты под правилом

| Маршрут | Вид (`type`) | AI | Страницы Scrapfly |
| --- | --- | --- | --- |
| `POST /api/config/schema` | `config_schema` | да | да |
| `POST /api/config/extract` | `config_extract` | да | да |
| `POST /api/config/promo` | `config_promo` | **нет** | да |
| `POST /api/config/tz` | `config_tz` | да | нет |
| `POST /api/analyze` | `analyze` | да | нет |
| `POST /api/patents/scan` | `patents` | да | нет |

`config_promo` AI не вызывает, но оплачивает страницы — двойная оплата это деньги и тогда, когда AI не падает (FR-001a).

---

## 2. Что прибавляется во входе

Ко всем шести телам добавляется одно поле:

```json
{ "analysisId": "6f0a…-…-…", "…": "прежние поля без изменений" }
```

| Условие | Поведение |
| --- | --- |
| `analysisId` — непустая строка | ключ строится, правило действует |
| поля нет, оно пустое или не строка | ключ **не** строится, правило не действует, случай отмечается в журнале и называется человеку (FR-014) |

Проверка существования анализа в базе **не делается**: ключ — это средство сопоставления двух запросов между собой, а не право доступа. Права уже проверены сеансом, а сам идентификатор ничего не открывает.

---

## 3. Что прибавляется в ответе

### Обычный запуск — как сегодня

```
202 { "jobId": "…" }
```

### Присоединение к идущей работе

```
202 {
  "jobId": "…",                    ← идентификатор ЧУЖОЙ, уже идущей работы
  "joined": {
    "startedBy": "Имя",
    "startedAt": 1763640000000,
    "differs": [ { "what": "модель", "mine": "…", "theirs": "…" } ]
  }
}
```

Код ответа тот же, поле `jobId` то же — путь подписки в клиенте не меняется (`public/js/ai.js:16` читает только `jobId`).

**`differs` может быть пустым** — это нормальный и частый случай: параметры совпали. Выдуманного расхождения появиться не должно (FR-011).

### Ошибки — прежние

`400` при негодном теле, `401` без сеанса, `429` при превышении часовой квоты. Новых кодов ответа не вводится.

---

## 4. Правило

При запуске операции с построенным ключом:

1. Найти в реестре работу под этим ключом.
2. **Если найдена и выполняется** → вернуть её `jobId` и блок `joined`. Новой работы не создаётся, фабрика не вызывается, AI не трогается, страницы не грузятся.
3. **Иначе** → создать работу, записать в реестр, вернуть `jobId` без `joined`.

Шаги 1–3 выполняются **одним синхронным участком**, без `await` между ними (D2).

Запись снимается в блоке `finally` задачи — **немедленно** после завершения любым из четырёх путей, без срока хранения (D6).

---

## 5. Сравнение параметров по видам

`paramsOf(type, body)` → набор; `diffParams(mine, theirs)` → массив расхождений.

| Вид | `model` | `asins` | `fields` | `batchSize` | `keyword` |
| --- | :---: | :---: | :---: | :---: | :---: |
| `config_schema` | ✓ | ✓ | — | — | — |
| `config_extract` | ✓ | ✓ | ✓ | ✓ | — |
| `config_promo` | — | ✓ | — | — | — |
| `config_tz` | ✓ | — | — | — | — |
| `analyze` | ✓ | — | — | — | — |
| `patents` | ✓ | — | — | — | ✓ |

- `model` = `body.options?.model ?? null`
- `asins` = число различных годных ASIN (после той же чистки, что делает `cleanAsins`)
- `fields` = идентификаторы полей схемы, отсортированные, через запятую — **не** вся схема: порядок полей и подсказки меняются при правке руками, а операция от этого другой не становится
- `batchSize` = `body.batchSize ?? null`
- `keyword` = `body.coreKeyword || body.niche`

**Никогда не сравниваются**: `listings`, `payload`, `prevTable`, `prevSchema` (D5).

### Человеческие имена

| Поле | В тексте |
| --- | --- |
| `model` | модель |
| `asins` | охват |
| `fields` | схема полей |
| `batchSize` | размер пачки |
| `keyword` | ключевое слово |

## 6. Контрольные примеры

| № | Что происходит | Ожидается |
| --- | --- | --- |
| A | A запускает `config_extract` по анализу N; через 1 с B запускает то же по N с теми же параметрами | один и тот же `jobId`; `joined.startedBy` = имя A; `differs` — **пустой** |
| B | То же, но B выбрал другую модель | один `jobId`; `differs` = `[{ what: "модель", … }]` |
| C | То же, но у B 40 ASIN вместо 150 и другая схема | один `jobId`; `differs` содержит «охват» и «схема полей» |
| D | A запускает `config_schema` по N, B — `config_tz` по N | **два разных** `jobId`, у обоих `joined` отсутствует |
| E | A запускает `config_extract` по N, B — `config_extract` по M | **два разных** `jobId`, у обоих `joined` отсутствует |
| F | Работа A завершилась ошибкой; B запускает ту же операцию | **новый** `jobId`, `joined` отсутствует |
| G | Работа A отменена; B запускает ту же операцию | **новый** `jobId`, `joined` отсутствует |
| H | Работа A идёт; B шлёт запрос **без** `analysisId` | **другой** `jobId`, `joined` отсутствует, в журнале отмечено |
| I | Два запроса отправлены одновременно, ответа на первый не ждут | один и тот же `jobId`; задач этого вида ровно одна |

---

## 7. Что в этом договоре не меняется

- `GET /api/jobs/:id` и `GET /api/jobs/:id/events` — без изменений, проверки владельца как не было, так и нет.
- `DELETE /api/jobs/:id` — без изменений: присоединившийся может прервать работу, и это **написано на кнопке**, а не запрещено (D8).
- Часовая квота на пользователя (`rateLimitPerHour`) — без изменений.
- Формат событий задачи (`stage` / `done` / `error` / `end`) — без изменений.
