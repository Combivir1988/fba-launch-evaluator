# Data Model: Одна операция одного анализа выполняется один раз

Хранения в базе **нет**. Всё, что описано ниже, живёт в памяти процесса ровно столько, сколько выполняется сама работа, и гибнет вместе с процессом — так же, как уже устроены сами задачи (`jobs` Map в `server/jobs.js`).

---

## 1. Ключ операции

```
key = `${type}\u0000${analysisId}`
```

| Часть | Откуда | Примечание |
| --- | --- | --- |
| `type` | вид операции | один из шести: `config_schema`, `config_extract`, `config_promo`, `config_tz`, `analyze`, `patents` |
| `analysisId` | тело запроса, поле `analysisId` | UUID, общий для всех, кто открыл анализ из общей истории |

**Ключ не строится**, если `analysisId` отсутствует или не строка. Запроса без ключа реестр не касается: ни находит, ни записывает (D3, D7).

---

## 2. Реестр идущих работ

Карта `byKey: Map<string, Job>` в `server/jobs.js`, рядом с существующей `jobs: Map<string, Job>`.

| Свойство | Значение |
| --- | --- |
| Ключ | строка из раздела 1 |
| Значение | та же самая задача, что лежит в `jobs` — не копия |
| Запись появляется | синхронно, в том же участке, где задача кладётся в `jobs` |
| Запись исчезает | синхронно, в блоке `finally` задачи, рядом с `push("end", …)` |
| Срок жизни | ровно время выполнения; срока хранения (TTL) **нет** |

**Запись исчезает раньше самой задачи.** Задача после завершения живёт ещё час (`TTL_MS`), чтобы вернувшийся человек получил результат; запись реестра такого срока иметь не должна — иначе завершившаяся операция запирала бы себя на час (D6).

Запись удаляется **по совпадению значения**: если в карте под этим ключом уже лежит другая, более новая задача, запись не трогается. Иначе завершившаяся старая работа сняла бы замок с только что начатой.

---

## 3. Параметры операции

Короткий именованный набор, по которому считаются расхождения. Строится из тела запроса функцией `paramsOf(type, body)` (`server/job-params.js`).

| Поле | Тип | Для каких видов | Что значит |
| --- | --- | --- | --- |
| `model` | строка \| null | schema, extract, tz, analyze, patents | выбранная модель AI; `null` — умолчание сервера |
| `asins` | число \| null | schema, extract, promo | сколько листингов в охвате |
| `fields` | строка \| null | extract | отпечаток схемы: отсортированные идентификаторы полей через запятую |
| `batchSize` | число \| null | extract | размер пачки |
| `keyword` | строка \| null | patents | ключевое слово |

Поля, которых у вида нет, отсутствуют в наборе (не `null`-заглушки) — иначе сравнение показывало бы расхождение «было null, стало null».

**Что в набор не входит и почему**: `listings` (кэш страниц, у двух людей законно разный — попади он в набор, расхождение возникало бы всегда и сообщение перестало бы что-либо значить), `payload`, `prevTable`, `prevSchema` (производные от уже посчитанного).

## 4. Расхождение параметров

```
{ what: "модель", mine: "…", theirs: "…" }
```

| Поле | Значение |
| --- | --- |
| `what` | человеческое имя параметра: «модель», «охват», «схема полей», «размер пачки», «ключевое слово» |
| `mine` | что задал присоединившийся |
| `theirs` | с чем идёт работа |

Считается функцией `diffParams(mine, theirs)` → массив. **Пустой массив — нормальное и частое значение**: параметры совпали, расхождений нет, и выдумывать их нельзя (FR-011).

Отсутствующее с обеих сторон поле расхождением не считается. Отсутствующее с одной стороны — считается, и показывается как «не задано».

---

## 5. Сведения о присоединении

Возвращаются вызывающему только когда он **присоединился**; при обычном запуске отсутствуют.

```
joined = {
  startedBy: "Имя Запустившего",
  startedAt: 1763640000000,
  differs: [ { what, mine, theirs }, … ]
}
```

| Поле | Откуда | Примечание |
| --- | --- | --- |
| `startedBy` | `job.meta.userName` | уже кладётся сегодня всеми шестью маршрутами |
| `startedAt` | `job.createdAt` | уже есть у задачи |
| `differs` | раздел 4 | может быть пустым |

`startedBy` берётся **только из памяти** (`req.user` / `job.meta`), без обращения к базе: любой `await` в этом участке вернул бы гонку (D2).

---

## 6. Что в задаче прибавляется

У существующего объекта задачи появляются два поля — и больше ничего:

| Поле | Значение |
| --- | --- |
| `key` | ключ раздела 1 или `null` (запрос без идентификатора) |
| `params` | набор раздела 3 |

`meta` (`niche`, `userId`, `userName`) остаётся как есть.

---

## 7. Состояния и переходы

```
нет записи
   │  запуск с ключом, под ключом никого
   ▼
ЗАПИСЬ ЕСТЬ ─── запуск с тем же ключом ──▶ присоединение (новой записи не появляется)
   │
   │  работа завершилась: успех │ ошибка │ отмена │ обрыв
   ▼
нет записи          (все четыре пути проходят через один finally — D6)
```

Запуск **без** ключа в этой схеме не участвует вовсе: он не создаёт записи и не находит чужую (D7).
