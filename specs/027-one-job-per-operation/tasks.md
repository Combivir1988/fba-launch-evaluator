## Phase 3: US1 — второй запуск не порождает второго прогона (P1) 🎯 MVP

**Цель**: AI вызывается один раз, страницы оплачиваются один раз, результат один.
**Независимая проверка**: T003–T006 зеленеют, T007–T009 зеленеют.

- [ ] T011 [P] [US1] Новый `server/job-params.js`: функция `jobKey({ type, analysisId })` → `` `${type}\u0000${analysisId}` `` или `null`, если `analysisId` не является непустой строкой. Разделитель `\u0000` не встречается ни в именах видов, ни в UUID (data-model.md §1).
- [ ] T012 [US1] В `server/jobs.js` завести карту `byKey` рядом с существующей `jobs` Map. **Комментарий про один экземпляр сервера ставится прямо над ней, в коде**, а не только в research.md: при двух и более экземплярах правило перестанет работать молча, каждый процесс будет видеть только свои работы (D10, замер поведением 2026-11-20).
- [ ] T013 [US1] В `server/jobs.js`: `startJob` принимает ключ и параметры, возвращает `{ job, joined }`. **Поиск по ключу и регистрация — ОДИН синхронный участок, без `await` между ними** (D2). Имя запустившего берётся только из `job.meta` / `req.user`; **обращений к базе в этом участке быть не должно** — любой `await` возвращает гонку.
- [ ] T014 [US1] В `server/jobs.js`: снятие записи из `byKey` в блоке `finally`, рядом с `push("end", …)`, **синхронно и немедленно**. ⚠️ **НЕ внутри `setTimeout(…, TTL_MS)`**: задача живёт час после завершения, и запись с таким же сроком заперла бы операцию на час. Удаление — **по совпадению значения**: если под ключом уже лежит более новая задача, запись не трогать, иначе завершившаяся старая работа снимет замок с только что начатой (data-model.md §2).
- [ ] T015 [US1] В `server/index.js`: все шесть маршрутов (`/api/config/schema`, `/api/config/extract`, `/api/config/promo`, `/api/config/tz`, `/api/analyze`, `/api/patents/scan`) передают ключ в `startJob`.
- [ ] T016 [P] [US1] В `public/js/ai.js`: `analysisId` добавляется в тело запроса для `analyze`, `patents` и общего пути `runConfigJob`. Идентификатор уже под рукой — им же ключуется `pendingJob` в localStorage.
- [ ] T017 [P] [US1] В `public/js/app.js`: `analysisId` добавляется в четыре вызова этапа 2 (схема, извлечение, промо, ТЗ).

## Phase 4: US2 — присоединившийся знает, что прогон не его (P1) 🎯 MVP

**Цель**: человек видит, кто запустил, когда, и чем его параметры отличаются.
**Независимая проверка**: контрольные примеры A, B, C из contracts/jobs.md.

- [ ] T019 [US2] В `server/job-params.js`: `paramsOf(type, body)` строго по таблице из contracts/jobs.md §5 — **не выдумывать**. `model`, `asins`, `fields`, `batchSize`, `keyword`; поля, которых у вида нет, в набор не попадают (не `null`-заглушки). `fields` — **отсортированные идентификаторы полей схемы через запятую**, а не вся схема: порядок полей и подсказки меняются при правке руками, а операция от этого другой не становится.
- [ ] T020 [US2] В `server/job-params.js`: `diffParams(mine, theirs)` → массив `{ what, mine, theirs }` с человеческими именами («модель», «охват», «схема полей», «размер пачки», «ключевое слово»). Пустой массив — нормальное и частое значение.
- [ ] T021 [P] [US2] Тесты контрольных примеров **A, B, C**: одинаковые параметры → `differs` пустой; другая модель → ровно одно расхождение «модель»; другой охват и другая схема → два расхождения.
- [ ] T022 [US2] **Главная ловушка решения D5**: тест «параметры одинаковые, а кэш `listings` разный» → `differs` **пустой**. В теле запроса едет кэш страниц, у двух людей он законно разный; попади он в набор — расхождение возникало бы **всегда**, и сообщение перестало бы что-либо значить (та же примета, по которой spec 019 переписала 1f, а spec 024 отказалась от условного сообщения).
- [ ] T023 [US2] Тест: на одинаковых параметрах `differs` пустой для **всех шести** видов, а не для одного «для примера». **Если хоть одно расхождение появляется — набор полей выбран неверно, и это повод ОСТАНОВИТЬСЯ, а не подправить текст сообщения.**
- [ ] T024 [US2] В `server/index.js`: ответ всех шести маршрутов при присоединении несёт блок `joined` = `{ startedBy, startedAt, differs }`. Код ответа остаётся 202, поле `jobId` остаётся тем же — путь подписки в клиенте не меняется (contracts/jobs.md §3).
- [ ] T025 [US2] В `public/js/ai.js`: `joined` из ответа доходит до вызывающего кода (сегодня из ответа читается только `jobId`).
- [ ] T026 [US2] **Ворота SC-004** (часть первая, по ответу сервера): тест проверяет **содержимое** — `joined.startedBy`, `joined.startedAt`, `joined.differs` присутствуют у присоединившегося и отсутствуют у запустившего. Проверяется содержимым, а не наличием кода (образец — SC-011a spec 021).

## Implementation Strategy

### Минимум, при котором правило работает = Phase 1–4 (T001–T026)
