# Quickstart: spec 002 — аккаунты, общая история, публичные ссылки

## Локальный запуск (без внешних сервисов)

```bash
npm install
npm run dev        # MOCK_AI=1, ADMIN_LOGIN=admin, ADMIN_PASSWORD=admin-dev-pass, БД — PGlite в .data/pg
npm test           # node --test, PGlite в памяти, внешняя сеть не нужна
```

Открыть http://localhost:3000 → войти `admin` / `admin-dev-pass` → приложение потребует сменить пароль. PGlite занимает ~700 MB RAM и стартует ~5 с — это нормально для разработки; в production он не используется.

Проверка на настоящем Postgres локально: `DATABASE_URL=postgres://… npm start` (миграции применяются при старте).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения Neon (pooled-хост `…-pooler…`, `?sslmode=require`). В production обязательна |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | первый администратор; создаётся при старте, только если в БД нет активного админа. Пароль ≥ 10 символов, при первом входе меняется |
| `MAX_JOBS` | общий предел одновременных AI-задач, по умолчанию 4 |
| `PUBLIC_URL` | базовый адрес для ссылок «Поделиться» (уже задан на Railway) |
| `AI_PROVIDER`, `OPENROUTER_*`, `MOCK_AI` | без изменений |
| ~~`APP_PASSWORD`~~ | удаляется после выпуска шага 1 |

## Создание базы (один раз, владелец, ~3 минуты)

1. neon.com → Sign up (без карты) → Create project: имя `fba-launch-evaluator`, регион Europe (Frankfurt), Postgres последней версии.
2. Connection string → включить **Pooled connection** → скопировать строку.
3. Вставить строку в локальный файл секретов (тот же, где токен Railway) как `DATABASE_URL=…`. В чат строку не вставлять.
4. Дальше переменные на Railway выставляются через GraphQL `variableCollectionUpsert`, деплой — `serviceInstanceDeployV2` с `commitSha` при `health.running = 0`.

## Проверка по историям

**US1 — аккаунты**
1. Войти админом → «Настройки → Пользователи» → создать `anna` (роль «пользователь») с временным паролем.
2. В другом браузере войти как `anna` → требуется смена пароля → после смены имя видно в шапке, раздела «Пользователи» нет.
3. 6 неверных паролей подряд → сообщение о временной блокировке; текст ошибки одинаков для несуществующего логина.
4. Админ отключает `anna` → в её вкладке следующий запрос в течение минуты ведёт на страницу входа.
5. Попытка админа отключить себя (единственного) → отказ «нужен хотя бы один администратор».

**US2 — общая история**
1. `anna` загружает Xray + Cerebro, анализ автосохраняется → у админа в «Истории» строка с «автор: Анна».
2. Фильтр «мои», поиск по нише и по автору.
3. Оба открывают один анализ; админ меняет цену и сохраняет; `anna` меняет COGS и сохраняет → диалог конфликта с именем и временем → «Сохранить как копию» создаёт второй анализ с автором Анна.
4. Войти в браузере со старой локальной историей → предложение переноса → число анализов выросло на число локальных → повторный перенос добавляет 0.
5. Запустить AI (mock), закрыть вкладку до завершения, открыть анализ на другом устройстве → результат на месте.

**US3 — «Поделиться»**
1. «История» → «Поделиться» → режим «полный», 30 дней → ссылка в буфере.
2. Приватное окно без входа → дашборд с графиками, шапка «Подготовил … · снимок от …», нет полей ввода и кнопок запуска; «Скачать HTML» работает; телефонная ширина 360 px читаема.
3. Изменить анализ → по ссылке прежний снимок; в списке ссылок пометка «анализ изменён после снимка» → «Обновить ссылку» → адрес тот же, данные новые.
4. Вторая ссылка в режиме «без закупочной экономики» → в исходнике страницы и скачанном HTML поиск значений COGS, маржи, ROI, бюджета ничего не находит.
5. «Отозвать» → в приватном окне после обновления единый экран «Ссылка недействительна…»; тот же экран для случайного адреса `/s/abc`.
6. Счётчик просмотров вырос на 1 за приватное окно; просмотры вошедшего пользователя не считаются.

**US4 — параллельность и журнал**
1. Два пользователя одновременно запускают AI на разных анализах → оба результата в своих анализах.
2. Второй запуск AI тем же пользователем → сообщение о личном лимите с названием идущей задачи.
3. `MAX_JOBS=1` → второй пользователь получает сообщение об общем лимите.
4. F5 во время задачи → подхват; открытие того же анализа другим пользователем → «задача идёт, запустил …».
5. «Настройки → Журнал задач»: записи с пользователем, моделью, длительностью, итогом; сводка по людям; у обычного пользователя — только свои.

## Автоматические проверки

- `npm test` — все прежние тесты + новые (пароли, сеансы, пользователи, анализы/конфликты, ссылки, снимок, лимиты, журнал, публичная страница в jsdom).
- `node scripts/ui-probe7.mjs` — сквозной сценарий в Chromium: вход → загрузка фикстур → сохранение → «Поделиться» → новый контекст без cookie → проверка дашборда → отзыв.
- После деплоя: `GET /api/health` → `running: 0`, `storage: "pg"`; вход админом; создание и открытие тестовой ссылки; RAM процесса по метрикам Railway < 300 MB.
