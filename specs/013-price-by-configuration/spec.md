# Feature Specification: Ценовой ориентир по конфигурации

**Feature Branch**: `013-price-by-configuration` · **Created**: 2026-09-23 · **Status**: Implemented (см. tasks.md → «Выпуск»)

## Проблема

После этапа 2 известно, какие характеристики собирают выручку, но цена своего товара по-прежнему берётся «на глаз» или как медиана всей ниши. Нужен ориентир: сколько стоят листинги именно такой конфигурации, как моя, что в ней здорожает товар и платят ли за это покупатели, и как это ложится на экономику.

## User Scenarios & Testing

### User Story 1 — Цена моей конфигурации (Priority: P1)

1. **Given** извлечена таблица характеристик, **When** менеджер открывает блок «Цена вашей конфигурации», **Then** по умолчанию выбраны доминирующие значения полей и показаны: рыночная цена (взвешенная выручкой медиана цен листингов-аналогов), «вход» (P25) и «потолок» (P75), число аналогов и доля совпавших полей; с учётом купонов — отдельно (spec 014).
2. **Given** менеджер меняет значения полей (свой товар), **Then** аналоги и цены пересчитываются мгновенно; выбор сохраняется с анализом.
3. Если аналогов с полным совпадением меньше 5, требование ослабляется до 80 %, затем 60 % совпавших полей — с честной пометкой; если и так меньше 3 — показывается предупреждение и цена по отдельным полям.

### User Story 2 — Вклад каждого поля (Priority: P1)

1. Таблица «поле · ваше значение · доминанта · Δ цены»: разница средней цены выбранного значения и доминирующего; ★ — за значение платят (премия).

### User Story 3 — В экономику и ТЗ (Priority: P2)

1. Кнопка «Подставить $X в экономику» записывает рыночную цену в поле «Цена» — Gate 1/2, ROI, бюджет, деньги по месяцам пересчитываются; если цена вне заданного ценового диапазона — предупреждение.
2. В фактах для ТЗ: целевая розничная цена, вход/потолок, число аналогов и ориентир себестоимости для пороговой маржи.

## Requirements

- **FR-001**: Расчёт детерминированный, в общем ядре (`shared/`), без AI; вес — выручка ASIN из Xray; цены — из Xray (текущая) и, если есть, с учётом купонов из промо листинга.
- **FR-002**: Совпадение полей — по нормализованным значениям; поля без выбранного значения не участвуют; текстовые поля не участвуют.
- **FR-003**: Ориентир себестоимости = цена × (1 − referral) − FBA-сбор − цена × минимальная маржа (пороги экономики).
- **FR-004**: Контрольные отпечатки прежних расчётов не меняются.

## Success Criteria

- **SC-001**: Для доминантной конфигурации с ≥ 5 аналогами показывается медиана и P25–P75; смена одного значения меняет набор аналогов и цену без перезагрузки.
- **SC-002**: «Подставить» меняет цену экономики за один клик.
