# Контракт: как именно считаются оба показателя

Это договор между расчётом и всем, что его читает: интерфейсом, AI, публичной ссылкой, разделом «Статистика». Формулы записаны так, чтобы по ним можно было написать тест, не заглядывая в код.

---

## Общее: на чём считается

Оба показателя считаются на **виде** — наборе листингов, который видит `competition` в `shared/compute.js`:

1. применён ценовой диапазон (spec 003), если он активен;
2. выброшены исключённые бренды;
3. в режиме «я уже в нише» выброшен свой бренд.

Никакого отдельного прохода по листингам быть не должно: любой второй источник набора рано или поздно разойдётся с первым, и цифры перестанут сходиться с остальной конкурентной картой. Это проверяется (SC-008).

Обозначения ниже: `B` — множество брендов вида, `L` — множество листингов вида.

---

## 1. Концентрация ниши

```
revenue(b)      = сумма выручки листингов бренда b
totalRevenue    = Σ revenue(b) по b ∈ B
share(b)        = revenue(b) / totalRevenue          (доля, 0…1)

hhi             = Σ (share(b) × 100)²  по b ∈ B      (число, 0…10 000)
```

**Единица**: число по шкале от около нуля до 10 000. Не процент. В интерфейсе печатается целым, без знака процента.

**Округление**: показывается округлённым до целого; сравнение с порогами идёт по неокруглённому значению.

**Статус подпункта 1f**:

| условие | статус |
|---|---|
| `hhi < hhiOk` | `ok` |
| `hhiOk ≤ hhi < hhiFail` | `warn` |
| `hhi ≥ hhiFail` | `fail` |

Умолчания: `hhiOk = 1500`, `hhiFail = 2500`.

**`null`**, если нет данных Xray, нет ни одного бренда или `totalRevenue = 0`. Подпункт тогда — «нет данных», а не ноль.

### Поясняющие числа

```
top5ListingShare = (сумма пяти наибольших выручек листингов) / Σ выручка по l ∈ L
listingCount     = |L|
```

`top5ListingShare` — доля, печатается процентом. `listingCount` — целое. Оба показываются **рядом** с концентрацией и **вместе**: поясняющее число без размера выборки вводит в заблуждение (в нише из 11 листингов пять крупнейших держат 92 % арифметически).

Если листингов меньше пяти, `top5ListingShare` равна 1 (все листинги и есть топ-5) — и именно поэтому рядом обязан стоять `listingCount`.

---

## 2. Летаргия бренда

```
reviewsSum(b)   = сумма отзывов листингов бренда b
totalReviews    = Σ reviewsSum(b) по b ∈ B
reviewsShare(b) = reviewsSum(b) / totalReviews       (доля, 0…1)

lethargy(b)     = (reviewsShare(b) + s) / (share(b) + s)
```

где `s` — **один** коэффициент сглаживания (`lethargy.smooth`, по умолчанию 0,01), прибавляемый и к числителю, и к знаменателю.

**Равенство слагаемых — часть контракта, а не настройка.** Следствие, которое обязано выполняться и проверяется тестом: если `reviewsShare(b) = share(b)`, то `lethargy(b) = 1` **точно**, при любом значении доли. Расчёт, в котором к числителю и знаменателю прибавляются разные величины, этот контракт нарушает.

**Единица**: отношение, безразмерное. Печатается с двумя знаками после запятой.

**`null`**, если `totalReviews = 0`. Тогда `lethargy` отсутствует у **всех** брендов ниши, и это состояние показывается словами, а не нулями.

### Ярлык

Проверяется в этом порядке:

```
если share(b) ≥ moneyMin и lethargy(b) ≥ giantMin   → "giant"
если share(b) ≥ moneyMin и lethargy(b) ≥ tiredMin   → "tired"
если lethargy(b) < efficientMax                      → "efficient"
иначе                                                → "normal"
```

Умолчания: `moneyMin = 0.10`, `giantMin = 2.0`, `tiredMin = 1.5`, `efficientMax = 0.8`.

Бренд с долей выручки ниже `moneyMin` **никогда** не получает `giant` или `tired`, каким бы большим ни был его индекс. Замер: брендов с индексом 5 и выше — 46, их медианная доля выручки 1,1 %; это мёртвые листинги, а не уязвимые гиганты.

### Доля денег у летаргичных марок

```
lethargyRevenueShare = Σ share(b) по тем b, у которых lethargy(b) ≥ tiredMin
```

Доля, печатается процентом. Порог по деньгам здесь **не** применяется: вопрос «сколько в нише плохо охраняемых денег», а не «кого конкретно двигать».

---

## 3. Чего расчёт делать не имеет права

- **Летаргия не участвует ни в одном решении.** Ни вердикт, ни статус любого критерия, ни чеклист, ни Scorecard не читают `lethargy`, `lethargyLabel` и `lethargyRevenueShare`. Проверяется сдвигом порогов летаргии до абсурда: ни одно решение не шелохнётся (SC-006).
- **Сохранённые результаты не переписываются.** Расчёт возвращает новые значения; то, что лежит в сохранённом анализе, остаётся как есть. Расхождение показывает раздел «Статистика» (FR-023).
- **Прежняя `top5Share` не удаляется.** Её читает критерий 5.

---

## 4. Контрольные значения для тестов

Из таблицы-образца (ниша цепей), при `s = 0.01`:

| бренд | доля отзывов | доля выручки | ожидаемая летаргия | ярлык |
|---|---|---|---|---|
| SHIMANO | 20,0 % | 35,5 % | 0,58 | `efficient` |
| SRAM | 10,6 % | 14,7 % | 0,74 | `efficient` |
| KMC | 26,5 % | 10,9 % | **2,31** | `giant` |
| Zonkie | 17,6 % | 5,9 % | 2,70 | `normal` (денег мало) |
| Silca | 0,1 % | 2,9 % | 0,28 | `efficient` |

Ожидаемые значения в таблице посчитаны **из приведённых здесь долей**; в самом образце у SHIMANO стоит 0,57, а не 0,58, и у Zonkie 2,69, а не 2,70 — расхождение возникает оттого, что доли в образце округлены до десятой доли процента. Тест обязан сверяться с расчётом по поданным на вход долям, а не с картинкой.

Концентрация по этим восьми брендам даёт 1 702; в таблице-образце указано 1 741 — разница от брендов, не попавших в показанные восемь строк. Для теста использовать значение, посчитанное по тому набору, который подан на вход.

Контроль равенства слагаемых (SC-007): бренд с `reviewsShare = share` даёт ровно `1.00` при доле 1 %, 3 %, 10 % и 30 %.
