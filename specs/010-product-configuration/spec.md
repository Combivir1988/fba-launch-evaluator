# Feature Specification: Этап 2 — конфигурация продукта и ТЗ производителю

**Feature Branch**: `010-product-configuration` · **Created**: 2026-09-22 · **Status**: Implemented — на проде 2026-09-22 (см. [tasks.md](tasks.md) → «Выпуск»); проба Scrapfly выполнена 2026-09-22
**Образец**: `C:\Users\User\Downloads\boxing machine.xlsx` — 61 ASIN × 23 характеристики, вручную извлечённые из листингов; 15 секторных диаграмм «характеристика → доля выручки»; листы анализа отзывов, патентов/FDA, проработки поставщиков.

## Проблема

Этап 1 отвечает «стоит ли заходить в нишу», но не отвечает «какой именно товар делать»: какая комплектация, материалы, размеры и функции собирают выручку ниши, а какие — редкость. Сейчас это делается вручную: по каждому листингу читаются тайтл, буллеты, характеристики и A+, значения переписываются в колонки, строятся диаграммы, из них и отзывов складывается ТЗ. На нишу из 60–100 ASIN — дни работы, а значения «расползаются» (в образце 53 уникальных значения одного поля).

## User Scenarios & Testing

### User Story 1 — Схема характеристик ниши (Priority: P1)

1. **Given** анализ с Xray, **When** менеджер запускает «Конфигурация продукта», **Then** приложение загружает страницы 15–20 самых продаваемых листингов и предлагает схему полей ниши: название, тип (число / выбор из списка / текст), допустимые значения, примеры из листингов.
2. **Given** схема предложена, **When** менеджер правит её (переименовать, удалить, объединить значения, добавить поле), **Then** схема сохраняется в анализе и применяется ко всем листингам.

### User Story 2 — Извлечение по всем листингам (Priority: P1)

1. **Given** утверждённая схема, **When** запущено извлечение, **Then** для каждого уникального ASIN из Xray (после исключения брендов) страница загружается через Scrapfly, AI заполняет поля строго значениями из списка схемы; нет данных — «нет данных», не догадка; у каждого значения сохраняется источник (тайтл / буллеты / характеристики / A+).
2. **Given** извлечение выполнено, **When** открыт результат, **Then** таблица ASIN × поля редактируется вручную; по каждому полю видно покрытие (доля листингов с данными) и доля страниц, которые не удалось загрузить.
3. **Given** страница загружена меньше 30 дней назад, **When** извлечение повторяется, **Then** страница берётся из кэша анализа без нового запроса.

### User Story 3 — Диаграммы «характеристика → выручка» (Priority: P1)

1. По каждому полю — секторная диаграмма долей выручки ниши по значениям (вес — ASIN Revenue из Xray); рядом абсолютная выручка, число листингов, средняя цена и доля листингов по каждому значению; «нет данных» — отдельный сектор.
2. «Доминирующая конфигурация»: по каждому полю значение с наибольшей выручкой; пометка «премия» — значение, у которого доля выручки выше доли листингов и средняя цена выше медианы поля.
3. Переключатель «вся ниша / мой ценовой диапазон» (spec 003).

### User Story 4 — ТЗ производителю (Priority: P2)

1. Таблица «параметр / требование / обоснование / приоритет (must / should)» собирается из: доминирующей конфигурации (база), негативных тем отзывов POE и выводов этапа 1 (где отличаться), регуляторных триггеров и патентного скана (что проверить), цен и комплектации (ориентир себестоимости).
2. Текст пишет AI по фиксированной структуре, все числа — из расчётов; просмотр и правка в приложении, затем экспорт DOCX; ТЗ хранится в анализе и попадает в историю версий.

## Итоги пробы Scrapfly (2026-09-22)

- Аккаунт: план DISCOVERY, лимит 200 000 запросов в месяц, остаток ≈ 104 500 на 22.09, параллельность 5. Ключ — `SCRAPFLY_API_KEY` в `.railway-secrets.env`; в код, репозиторий и чат не попадает.
- Запрос `GET https://api.scrapfly.io/scrape?key=…&url=https://www.amazon.com/dp/{ASIN}&asp=true&country=us&render_js=false&extraction_model=product` → 200. В `result.extracted_data.data`: `name`, `brand`, `description` (буллеты строками), `specifications[]` (таблица характеристик Amazon: Brand Name, Material, Number of Items, Item Dimensions, Item Weight…), `images[]` (7–13 штук, в HTML есть hiRes), `variants[]` (цвета / размеры), `offers[0].price`, `aggregate_rating`, `main_category`.
- Стоимость: 26–31 кредит на страницу (5 — модель извлечения, 20–25 — надбавка за размер HTML 1,7–2 MB, 1 — прокси). 100 ASIN ≈ 3 000 кредитов. Дешевле — без `extraction_model`, разбирая HTML самим (`#feature-bullets`, `productDetails_techSpec`, `productOverview`); решить при реализации.
- **A+ почти целиком картинки**: текста в модулях 0–180 знаков. Характеристики из A+ и карусели — отдельный шаг чтения изображений моделью со зрением (P2, после текстового покрытия).
- Xray содержит дубли ASIN (строки вариаций) — брать уникальные. В топе выручки «amaranthus» оказались гортензии и ветки (contamination) — фильтр исключённых брендов применять до загрузки.
- Скрипт пробы: `scripts/scrapfly-probe.mjs` (ключ только из окружения).

## Requirements

- **FR-001**: Загрузка страниц — только через сервер (ключ на сервере), фоновой задачей с прогрессом и возобновлением (как AI-задачи); кэш страниц и извлечения в анализе на 30 дней; не больше 150 ASIN за запуск.
- **FR-002**: Схема полей — предложение AI плюс правка менеджера; значения полей типа «выбор» — только из списка схемы.
- **FR-003**: Извлечение — структурированный вывод AI по схеме, с источником и честным «нет данных».
- **FR-004**: Диаграммы и «доминирующая конфигурация» считаются детерминированно из таблицы; вес — ASIN Revenue.
- **FR-005**: ТЗ — по фиксированной структуре, числа только из расчётов; экспорт.
- **FR-006**: Всё хранится в анализе (общая история, версии); в публичную ссылку по умолчанию попадают диаграммы и таблица, но не ТЗ.

## Success Criteria

- **SC-001**: Ниша до 100 ASIN — извлечение за ≤ 15 минут и ≤ 4 000 кредитов Scrapfly.
- **SC-002**: Покрытие пяти ключевых полей схемы ≥ 70 % листингов; остальное честно «нет данных».
- **SC-003**: Сумма долей выручки по каждому полю — 100 % (с сектором «нет данных»).
- **SC-004**: ТЗ формируется одной кнопкой; каждое число в нём ссылается на источник (поле диаграммы, тема отзывов, триггер).

## Решения владельца (2026-09-22)

1. **A+ и карусель**: первая версия работает только с текстом (тайтл, буллеты, таблица характеристик, текст A+ если есть). Чтение изображений — отдельный этап после оценки покрытия.
2. **ТЗ производителю — DOCX**. Сначала ТЗ показывается в приложении (содержание таблицей, можно править), затем кнопка «Скачать DOCX». XLSX не нужен.
3. **Лист «проработка поставщиков» не нужен вообще** — вне объёма.

Уточнение к US4: экспорт только DOCX; в интерфейсе — просмотр и правка перед скачиванием.
