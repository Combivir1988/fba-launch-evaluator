# Implementation Plan: Этап 2 — конфигурация продукта и ТЗ производителю (spec 010)

**Spec**: [spec.md](spec.md) · **Date**: 2026-09-22 · **Migrations**: нет (всё внутри документа анализа) · **Новые зависимости**: `docx` (MIT, только сервер — сборка DOCX) · **Новые переменные окружения**: `SCRAPFLY_API_KEY` (только сервер; в браузер, журнал и репозиторий не попадает)

## Technical Context

Node 22 + Express 5, vanilla ES-modules, Chart.js; расчётное ядро `shared/*.js` общее для браузера и `node --test`; фоновые задачи через `server/jobs.js` (SSE с replay, восстановление после F5 через `pendingJob`); AI — `openrouterJson()` (каскад json_schema → json_object → text, проверка по схеме `validateVerdict`), модель — выбор пользователя «AI-вердикт» (по умолчанию `aistudio/gemini-3.5-flash-lite`); хранение — `core` JSONB (≤ 1 MB) + `aggregates_gz` (≤ 3 MB gz) с optimistic lock и историей версий (spec 009); публичные ссылки — `buildSnapshot()`; автономный HTML — inline `render.js`. Scrapfly проверен пробой (spec.md, «Итоги пробы»).

## Design decisions

- **D1 — Хранение без миграции.** Лёгкое состояние этапа 2 — в `core.config = { schema, table, tz, scope }` (см. [data-model.md](data-model.md)); кэш страниц — в `aggregates.listings[asin]` (только текст: тайтл, буллеты, таблица характеристик, текст A+, цена, рейтинг, варианты, число картинок; без HTML, картинок и отзывов). Свежесть кэша — `fetchedAt` не старше `thresholds.config.cacheDays` (30). Оба поля ходят по существующим `PUT /api/analyses/:id` и `…/aggregates`, попадают в историю версий и в `metaFromCore` (флаг `configDone`).
- **D2 — Scrapfly только на сервере** (`server/scrapfly.js`): ключ `cfg.scrapflyKey` из `SCRAPFLY_API_KEY`; запрос как в пробе (`asp=true&country=us&render_js=false&extraction_model=product`, плюс `cost_budget=60` — страховка от неожиданной надбавки); ответ нормализуется в текстовую запись `listing` (D1); стоимость — из `context.cost.total`. Параллельность 3 (план даёт 5), повтор при 429/5xx до 2 раз с паузой; 401/402/403 (ключ/кредиты) — задача останавливается с понятной ошибкой, уже загруженные страницы сохраняются. `/api/health` отдаёт `scrapfly: true|false`; без ключа (и не в MOCK) маршруты этапа 2 отвечают 400 «Scrapfly не настроен».
- **D3 — Три фоновые задачи через `startJob`** (`server/config-jobs.js`): `config_schema` (загрузить топ-15 по выручке → AI предлагает схему полей), `config_extract` (догрузить недостающие/устаревшие страницы всех ASIN области → AI заполняет таблицу пачками), `config_tz` (AI пишет ТЗ по фактам). События `stage {stage: fetch|ai, done, total, text, cost}`; `done` несёт результат **и** загруженные страницы; клиент кладёт их в документ и сохраняет обычным путём (как AI-вердикт и патенты сегодня) — одна модель сохранения, без серверной записи в `aggregates_gz` и конфликтов версий. После F5 задача подхватывается через `pendingJob` (результат живёт на сервере 1 час). Все три маршрута — под существующим `limiter` (20/ч на пользователя).
- **D4 — Область ASIN** (`shared/config-scope.js`, чисто): уникальные ASIN Xray (парсер уже отбрасывает дубли) минус `inputs.excludedBrands` (без учёта регистра), по убыванию `asinRevenue`, не больше `thresholds.config.maxAsins` (150). Для схемы — первые `topForSchema` (15). Ценовой диапазон область НЕ сужает (грузим всю нишу; диапазон — переключатель на диаграммах).
- **D5 — Схема полей от AI** (`server/config-prompts.js`, схема `FIELDS_SCHEMA`): вход — ниша, ключ, 15 листингов текстом (тайтл, буллеты ≤ 1 200 знаков, характеристики ≤ 25 строк); выход — `fields[3..25]` `{ id (латиница snake_case), name (рус.), type: choice|number|text, unit, options[2..10] для choice, hint }`. Постобработка: уникальные id, обрезка до 25 полей, значения без дублей. Менеджер правит в диалоге `#schema-dlg` (переименовать, тип, единица, значения через запятую, удалить, добавить); переименование значения перезаписывает его в уже извлечённой таблице (так «объединяются» значения).
- **D6 — Извлечение** (`shared/config-extract.js` для нормализации, промпт в `config-prompts.js`, схема `EXTRACT_SCHEMA`): пачки по `batchSize` (6) листингов на один вызов AI, две пачки параллельно; правило промпта — «значение только из списка; нет в тексте — "нет данных"; источник title|bullets|specs|aplus». Нормализация: значение приводится к варианту схемы (регистр/пробелы/точное совпадение), число разбирается из строки (`"12.5 lb"` → 12.5), непонятное → `null` + `raw` для менеджера; пустой листинг (страница не загрузилась) → строка со статусом `failed`. Ручные правки клеток (`source: "manual"`) при повторном извлечении сохраняются. По каждому полю считается покрытие.
- **D7 — Диаграммы детерминированно** (`shared/config-stats.js`, вызывается из `compute()` → `results.config = { whole, band|null }`): вес — `asinRevenue` (если пусто — `price × asinSales`, иначе 0); группировка по нормализованному значению; поля-числа — как дискретные, пока различных значений ≤ `numericDistinctMax` (12), иначе 5 квантильных интервалов; сектор «нет данных» всегда есть — сумма долей 100 % (SC-003). По значению: выручка, доля выручки, число листингов, доля листингов, средняя цена, `premium` (доля выручки > доли листингов **и** средняя цена > медианы цен листингов поля с данными). `dominant` — значение с наибольшей выручкой (без «нет данных»). `band` считается по `inBand(price, priceBand)`.
- **D8 — Интерфейс — две секции дашборда** в `render.js`: `config` (после «Тональность отзывов») и `tz` (перед «Заключение»); пустые — скрыты (как сегодня любая секция без данных). В секции `config`: шапка со счётчиками (ASIN в области / страниц загружено / извлечено / кредитов), кнопки шагов (не в static-режиме) «1 · Предложить схему полей», «Править схему», «2 · Извлечь характеристики», переключатель «вся ниша / мой диапазон», сетка секторных диаграмм (Chart.js doughnut, ≤ 8 секторов + «прочее», «нет данных» серым), таблица «Доминирующая конфигурация» (поле · значение · доля выручки · доля листингов · средняя цена · премия), `<details>` с полной таблицей ASIN × поля (в приложении клетки-`<select>`/`<input>`, в static — только чтение) и списком незагруженных страниц. Секция `tz`: кнопка «3 · Составить ТЗ», таблица с редактируемыми клетками, «⬇ Скачать DOCX». Подсказки — в словарь `TIPS`/`KEY_TIPS` (spec 006). Обновление через `update(dash, A, opts, ["config"])`.
- **D9 — ТЗ производителю**: факты собирает `shared/tz-payload.js` (доминирующая конфигурация с числами, «премиальные» значения, ценовые сегменты и медианная цена, темы отзывов POE (`poe.pdr` негатив/позитив), регуляторные триггеры, итог патентного скана, гипотезы дифференциации AI-вердикта, размер первой партии из бюджета); AI по схеме `TZ_SCHEMA` `{ title, summary, rows[{ section, param, requirement, rationale, priority: must|should, source }], openQuestions[] }`; постпроверка чисел — каждое число в требовании/обосновании должно встречаться среди чисел пейлоада, иначе строка получает пометку `unverified` (чип «проверьте число»). Правки менеджера — в `core.config.tz.rows`. DOCX строится на сервере (`server/tz-docx.js`, пакет `docx`): `POST /api/tz/docx` с телом `{ tz, meta }` → вложение `TZ-<slug>-<дата>.docx`, разделы по `section`, таблица требований, «Открытые вопросы», подвал «числа — из расчётов приложения, дата».
- **D10 — Публичная ссылка и HTML**: `buildSnapshot()` удаляет `config.tz` (FR-006) и `aggregates.listings` (диаграммам и таблице кэш страниц не нужен); диаграммы и таблица остаются в обоих режимах (средняя цена — рыночная, не закупочная). Автономный HTML — всё как в приложении, в static-режиме.
- **D11 — Пороги**: группа `config` в `DEFAULT_THRESHOLDS`: `{ topForSchema: 15, maxAsins: 150, cacheDays: 30, batchSize: 6, numericDistinctMax: 12 }` + подписи в «Пороги».
- **D12 — MOCK-режим**: при `cfg.mock` `server/scrapfly.js` не ходит в сеть, а строит листинг из тайтла Xray (`mockListing`), `server/mock-config.js` даёт схему из ключей характеристик и заполняет таблицу точным совпадением — так работают тесты, `npm run dev` и проба `ui-probe17` без кредитов и ключей. Контрольные отпечатки результатов не меняются: `results.config` попадает в `stripNew`.
- **D13 — Что не делаем сейчас**: чтение картинок A+/карусели (P2 после оценки покрытия), собственный разбор HTML вместо `extraction_model` (дешевле, но откладываем до реальной статистики кредитов), XLSX, лист поставщиков (решения владельца 2026-09-22).

## Constitution Check

Конституция проекта не заполнена (шаблон) — формальных ворот нет. Проектные правила соблюдены: ядро расчётов чистое и тестируемое в `shared/`, секреты только в окружении, никаких новых таблиц без необходимости, интерфейс на русском, справка обновляется тем же коммитом.
