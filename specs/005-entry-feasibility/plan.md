# Implementation Plan: Реально ли сюда зайти (spec 005)

**Spec**: [spec.md](spec.md) · **Date**: 2026-09-20 · **Migrations**: нет · **Новые зависимости**: нет

## Summary

Восемь доработок методики — чистые функции в `shared/`, подключённые в `compute()`; новые секции дашборда в `public/js/render.js`; шесть новых входных полей в панели; пороги в `thresholds.js`; AI-пейлоад и промпт; режим ссылки «без закупочной экономики» удаляет помесячные деньги вместе с остальной экономикой. Сервер, БД и API не меняются.

## Technical Context

Node 22, vanilla ES modules без сборки, Chart.js; расчётное ядро `shared/*.js` одно для браузера и `node --test`; рендер — классический скрипт `window.FBARender` (инлайнится в автономный HTML). Пересчёт — всегда полный `compute()` (≈ миллисекунды), ползунки обновляют секции из `ECON_DEPENDENT`.

## Constitution / принципы проекта

- Детерминированные расчёты, AI только синтез — соблюдено: всё считается в `shared/`, AI получает готовые цифры.
- Ничего не выдумывать при нехватке данных — каждая функция возвращает `reason`, когда данных мало.
- Публичный репозиторий: код и тексты собственные, сторонние материалы не копируются.
- Обратная совместимость анализов: новые поля получают значения по умолчанию в `defaultInputs()`/`migrate()`.

## Design decisions

- **D1 — один модуль на смысловой блок.** `shared/entry.js` (продажи на 1 % кликов, когорта, достижимость, барьер отзывов, цена по кликам, ловушки данных POE), `shared/cashflow.js` (помесячные деньги), `shared/borderline.js`, `shared/regulatory.js`. Результаты — новые ключи верхнего уровня `results.entry`, `results.cashflow`, `results.clickPrice`, `results.borderline`, `results.regulatory`, `results.dataNotes`; существующие структуры (criterion1, competition…) не трогаются.
- **D2 — вся ниша, не ценовой диапазон.** `entry`/`clickPrice`/`regulatory` получают `whole` (до `applyPriceBand`): внимание покупателей по цене не делится (FR-013).
- **D3 — опорная дата возраста листинга** = `poe.meta.capturedAt` → `analysis.createdAt` → «сейчас». Открытый через год анализ показывает те же возрасты, тесты детерминированы.
- **D4 — возраст по Xray `creationDate` (дата ASIN), запасной — POE `launchDate` (дата вариации) с пометкой.** Расхождение > `entry.dateGapDays` (90) попадает в `dataNotes`.
- **D5 — «наследник отзывов»**: отзывов больше, чем `продажи/мес × возраст × entry.inheritedReviewRate (10 %) + 50`. Нужен Xray (продажи); без него проверка не выполняется и это названо.
- **D6 — достижимость информационная** (FR-004): статус `ok / warn / fail` относительно долей кликов когорты (≤ P75 / ≤ P90 / выше), без когорты — по числу товаров ниши с такой долей (≥ 5 / 1–4 / 0); `preliminary: true`; в `verdictCeiling` не участвует. Обратная задача: до какой цели (шт/день) статус остаётся зелёным/жёлтым.
- **D7 — помесячные деньги** (`cashflow`): месяц 0 — оплата первой партии и стартовых расходов; продажи начинаются через `L = max(1, round(leadDays / 30))` месяцев; разгон линейный от стартового уровня (ввод → медиана когорты → 0) до цели за `rampMonths`; дозаказ в начале месяца, если «склад + в пути» не покрывает спрос на `L + 1` месяцев вперёд, объём — спрос `L + 1` месяцев после прихода, только если партия успевает прийти до конца горизонта; партия оплачивается при заказе целиком по landed-себестоимости; поступления = продажи × (цена − referral − FBA) — **себестоимость с продаж не вычитается** (SC-003); реклама = продажи × доля PPC × CPC ÷ CVR, до планки отзывов CVR × `newListingCvrFactor` (0,7); отзывы накапливаются как Vine + доля × продажи. Итоги: пик вложений, число партий, месяц возврата (после него итог не уходит в минус), остаток товара на складе в конце.
- **D8 — стоп-вопрос о бюджете по пику вложений** (FR-007): `budget()` получает `ctx.cash`; `need` = пик, `needTwoBatches` = прежняя сумма (справочно), допуск −15 % прежний. Это намеренная смена методики → `METHODOLOGY_VERSION = "2026-09-20"`. Совместимость остального доказана отпечатком: `tests/helpers/results-hash.js` исключает `budget`/`verdict`/новые ключи, контрольные значения сняты на коде до изменений (`scripts/baseline-hash.mjs`).
- **D9 — пограничные значения**: общий сборщик по уже посчитанным показателям с числовым порогом (1a–1h, Gate 1, ROI, 2j/2k, топ-2 ключей, релевантные ключи, бюджет, достижимость); `|value − threshold| / threshold ≤ borderline.pct (0,15)`; формулировка «сейчас X, порог Y, оценка изменится при …».
- **D10 — регуляторные триггеры**: собственная таблица правил (ведомство, тип `product|claim`, слова-регулярки, смысл) по английским словам; источники — ниша, главный ключ, заголовки Xray/POE (топ-50), запросы POE/Cerebro (топ-30). Для `claim` показывается доля заголовков с обещанием. Статус — всегда «допущение».
- **D11 — публичные ссылки**: в `no_economics` удаляются `results.cashflow`, `results.borderline` (экономические строки) и новые экономические входы; страховочная проверка утечек дополняется значениями cashflow.

## Risks

- Фикстуры Xray (велокамеры) и POE (urinal screen) — разные ниши, пересечения ASIN нет → тесты достижимости строят синтетическое пересечение поверх реального POE (продажи назначаются детерминированно).
- Стоп-вопрос о бюджете может поменять вердикт старых анализов при повторном открытии — версия методики в шапке это показывает; описано в справке.
